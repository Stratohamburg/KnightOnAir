# Design

## Context

`GameApp` 目前直接用时代选择出击，`World` 负责固定步进、遭遇、伤害与结算。现有风场已用于飞行、弹道和轰炸，渲染器将其传给云与植被。场景主光、体积云照明和云影当前包含各自的固定日照参数。变更动机见 [proposal.md](proposal.md)。

## Goals / Non-Goals

**Goals**

- 让关卡内容从出击到结算可追踪，并能用固定种子覆盖目标时序和环境变化。
- 复用时代内容、飞行控制、武器、路线和 2D、3D 内容库。
- 让移动端各画质使用一致的任务和环境语义。

**Non-Goals**

- 真实地理位置与设备实时时钟同步。
- 战役内跨时代、过场演出或新的武器输入体系。

## Decisions

### 关卡数据和任务状态

关卡配置以稳定 ID 排序，引用时代、当前目标组、开局机体或任务装配、遭遇、天气与时段。关卡序号用于显示。关卡入口解析配置，运行中的任务保存目标实例、活动阶段、相关倒计时与唯一终局。用同一验证入口检查关卡引用、阶段连通性、装配目标层、友方攻击者的武器兼容性及路线边界。由时代直接充当关卡身份会使同一时代的两个关卡相互覆盖。

任务状态在模拟固定步进末尾判定，先结算伤害，再按玩家坠毁、任务失败、阶段完成的顺序决策。受拦截目标只有存活越线才触发失败。标记目标与实际载体以实例身份关联，击毁奖励维持现有流程。由渲染帧驱动任务会使暂停、不同帧率和回放下的事件顺序不一致。

### 编排遭遇与友方对象

现有导演继续处理波次预算、视野外生成和安全间隔。把配置中的必需目标放入独立生命周期，先为它预留容量，再允许普通遭遇占用剩余预算。固定靶可在入场前安全布置，后续教学靶可提前布置并按编排激活。必需动态目标配置安全的替代入场候选和可交战窗口，普通请求的过期不会结束目标生命周期。导演等待时向任务提供入场方向，目标进入可交战状态后才启动期限。

友方目标进入可查询的战斗对象集合，路线推进和可受损性使用与其他载体相容的数据。允许特定敌人把指定友方对象作为选敌锚点，射程、目标层、碰撞和伤害仍由武器与伤害规则统一判定。把友方生命写成随时间下降的脚本会使玩家拦截行为与目标受损脱节。

### HUD 和结算的数据流

应用从任务读取展示状态，将任务文本和进度传给战斗状态栏，将任务位置、队伍和紧迫度传给雷达与边缘标。沿用组件、投影路径和节点池，HUD 上的告警和操作提示消费事件或快照。普通名牌可随云遮挡淡出，任务身份和可行动的方向通过保留的导航标显示。

战役出击与自由巡航分别选择。结算使用模拟发布的唯一结果，按一次出击写入统计，按关卡 ID 保存通关。重试以同一关卡配置和初始种子重建世界，下一关走正常简报与出击流程。

### 天气与日夜共享时钟

天气状态提供云量、能见度、雨量和风场参数，日夜状态提供起始时段、进度与光照参数。两者可以各自保持固定或响应编排触发，在固定步进中从当前有效状态开始过渡。风场是飞机、弹道和环境表现的共同输入。演示与旧出击调用可使用兼容默认值，时段和天气都由对应的场景上下文选择。按设备系统时间推进会使同一关的教学与回放取决于运行时间。

渲染端从同一时段计算主光、环境光、天空与表面光照。云渲染和云影共享日照方向，在地平线附近平滑减弱需要正太阳高度的采样项，夜间使用有界的低光表现。天气影响云、雾、雨以及光照外观，视觉品质控制采样和粒子数。渲染对快照的插值可改善连续性，暂停时采用当前模拟状态。给每个材质各自设置一套日夜计时会造成过渡不同步。

## Risks / Trade-offs

- **目标候选长期无法放置** → 用固定种子覆盖多个玩家航向与饱和预算，验证预留与备选点，等待时保持明确的入场提示。
- **武器兼容性与伤损阻断通关** → 出击前校验必需挂载和目标层。试玩检查必需挂载容易失效的关卡是否需要可达维修窗口。
- **低光、降雨和 HUD 同时降低可读性** → 在竖屏各画质检查友机与威胁重叠、屏内外切换、准心和告警。夜间使用任务标记的形状与文字识别身份。
- **短关内升级与积分节奏变化** → 关卡进度按通关保存，仍可自由巡航取得既有长期奖励。试玩调节关卡补给、装甲、数量和时间窗口。

## Migration Plan

1. 读取有效档案时为缺失的战役字段提供空记录，由配置解锁第 01 关。独立校验关卡记录，沿用其余字段的读取和装备校验。
2. 先打通固定靶、移动靶、列车和海峡护航的出击到结算路径，再装入完整 20 关与环境配置。
3. 在旧档案、自由巡航和战役重试场景验证回归。仅在战役内容校验通过后开启战役出击入口。

## Open Questions

- 敌机生命、可用补给、限时窗口、天气过渡持续时间和夜间最低亮度由竖屏试玩调定。
