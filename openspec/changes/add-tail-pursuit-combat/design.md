# Design

## Context

See `proposal.md` for the motivation. 当前空战已经通过共享 `ControllerIntent` 和 `integrateAirActor` 推进玩家、NPC 与回放。`npcIntent` 每步直接根据玩家预测位置产生目标航向，缺少飞行员感知、战术承诺、动作滞后和武器解算。导演、NPC 决策和飞行动力学需要明确分层。

## Goals / Non-Goals

**Goals**

- 让 NPC 通过相对几何感知和角色战术生成连续的飞行员行为。
- 让普通追猎机从后方或侧后方进入，并在玩家直线巡航时建立可读的尾后射击窗口。
- 让玩家转弯或加力逐步破坏尾后几何，敌人沿横向脱离或超越后重新切入。
- 保留截击机的高速掠过、轰炸机的路线攻击和护航机的锚点行为。
- 让角色级战术与飞行参数由配置表达，并通过固定步测试验证。

**Non-Goals**

- 不改变共享飞行动力学、武器伤害、相机朝向或 HUD 布局。
- 不把所有空中敌人改成持续追踪玩家的高机动单位。
- 不新增网络同步、存档字段或新的运行时依赖。

## Decisions

### 飞行员决策闭环

每个固定步先从玩家和邻机快照推导相对距离、相对方位、目标航向差、闭合速度、横向偏差、双方速度、能量和武器解算结果。角色策略根据这些输入选择一个短时动作意图，再交给共享飞行积分器。控制器不直接写入位置或速度。

动作意图使用有限状态和滞后计时器表达。状态包括 search、approach、position、attack、defend、break、reengage 和 flee。状态转换需要满足进入阈值和离开阈值，避免敌机在攻击与脱离之间每帧抖动。

### 角色级战术参数

在 `AirAttackProfile` 增加尾追距离、尾追保持时间、失位角度、脱离侧向偏移、动作冷却和武器解算容差。普通 `chase` 使用尾追参数，`intercept`、`dive` 和路线型行为继续使用各自的攻击窗口。参数放在内容配置中，避免控制器按敌人 ID 分支。

### 追猎机动作

追猎机使用 lag pursuit 接近玩家后方或侧后方的预测目标点。进入尾后距离带后改为速度匹配和小幅侧向修正，保留射界需要的横向偏差。它不会每帧重新选择玩家当前位置作为目标点。

### 截击机和其他角色动作

截击机使用 lead pursuit 计算交会点，以较高速度完成短时攻击后继续延长航线并超越目标。俯冲机、横穿机、护航机和轰炸机分别围绕攻击轴、路线点或护航锚点行动。导演只给出角色和入口，生成后的路线由角色策略持续决定。

### 射击与防御决策

敌人只有在攻击角、射程、闭合速度和预测命中误差同时满足时才开火。开火后进入短时动作承诺，避免每帧改变目标。玩家进入敌人后半球、敌人失去能量优势或关键部件受损时，策略优先脱离、重新占位或逃逸。

### 失位后的两段脱离

玩家持续转向时，追猎机先进入 `breaking`，沿攻击航向外侧偏移并提高油门。距离达到脱离阈值后进入 `reentering`，从预测位置和侧向偏移重新建立切入路线。敌人不会因为一帧方向变化直接回到玩家当前位置。

### 生成方向与安全校验

导演只为角色选择刷新时间、编组和后方或侧后方入口。生成仍复用现有安全距离、视口可见性和空中分离校验。入口方向以玩家航向计算，视口检查继续由渲染器提供，避免在屏幕内突然出现。生成完成后导演不再替 NPC 逐步决定航向。

### 保持其他角色差异

`intercept` 继续使用更高的攻击油门和加力，并在攻击后保持脱离航向。`crossing`、`standoff`、`escort` 和 `patrol` 保持路线或锚点优先。只有 `chase` 使用尾后保持目标点。

### 可观察性与测试

测试直接读取相对距离、相对速度、目标方位、战术状态转移、动作承诺和射击事件。遥测继续记录 `air_phase`，不新增持久化字段。固定种子测试需要验证同一输入下的战术决策确定性。

## Risks / Trade-offs

- [猎手转向率提高后会压制低机动玩家] -> 只提高追猎角色的转向响应，并保留生命阈值逃逸和玩家加力脱离窗口。
- [飞行员策略在固定步中抖动] -> 使用进入和离开阈值、动作承诺计时器和确定性随机扰动。
- [追猎机与玩家形成不可逃脱的闭环] -> 保留能量、转向、失位角度、受损逃逸和脱离距离约束。
- [后方生成可能落在固定相机视锥内] -> 每个候选点继续经过 `isSpawnVisible`，失败时重试侧后方候选。
- [攻击窗口延长后敌人火力过强] -> 射击仍受武器解算、射程、射界、冷却和伤害规则限制。

## Migration Plan

1. 扩展行为配置、相对几何快照和敌人战术状态字段，保持旧 profile 的默认值可运行。
2. 建立飞行员策略层，让 chase、intercept、dive 和路线攻击角色输出不同的控制意图。
3. 调整导演只负责刷新与入口，把逐步行为交给 NPC 策略。
4. 增加固定种子空战测试并调整角色级参数。
5. 更新主规格、玩法文档和验证记录。
6. 运行 `npm test`、`npm run check` 和 `openspec validate --strict "add-tail-pursuit-combat"`。
