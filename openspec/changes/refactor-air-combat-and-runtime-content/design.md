# Design

## Context

`World` 已经让玩家和 NPC 调用 `integrateAirActor`，但敌机调用前会按距离改写极速，玩家的风场和加力储备也在单独路径处理。`HitTest` 只扫掠有效部件，`World.damageEntity` 将伤害截断到该部件的剩余生命。玩家和敌机模型分别由 `ProceduralAircraft` 和 `Renderer.createEnemy` 拼装，战斗事件还缺少供特效使用的接触位置和发射姿态。产品范围见 [提案](proposal.md)。

## Goals / Non-Goals

以固定步进下的运动和伤害结算为准，使用同一份构型定义驱动碰撞、挂点和外观。战斗与机库通过现有入口接入。云、地形、路线和轰炸继续由各自规格管理。空战高度表现沿用 XZ 战斗平面上的三维姿态。

实施时将本变更的增量与对应主规格合读。飞行包线、分离和时代配置另见 [遭遇导演](../../specs/battle/encounter-director/spec.md)、[时代内容](../../specs/world/combat-content-and-eras/spec.md) 和 [战斗生命周期](../../specs/battle/session-lifecycle/spec.md)。改装后构型和状态见 [飞机改装](../../specs/battle/aircraft-refit/spec.md)，威胁提示、命中音频和资源验收见 [战斗反馈](../../specs/battle/battle-hud-and-event-feedback/spec.md) 和 [渲染质量](../../specs/rendering/quality-and-performance/spec.md)。内容库实施使用 [项目 skill](../../../.agents/skills/runtime-content-library/SKILL.md)。

## Decisions

### 控制器和飞行模型

将加力消耗、回充和重启门限、油门与风响应归入共享空中控制路径。输入端处理玩家触控、回放采样或 AI 意图。按当前构型解析质量、翼展、翼载、巡航、极速和滚转约束，阶段切换通过油门、刹车或加力实现。出场后只能通过共享积分器推进。现有每帧改写速度上限的做法会盖过惯性，因此从空中 NPC 路径移除。

各时代以常用战斗机的巡航、持续满油门与短时加力速度调校，避免把数值绑定到玩家当局机型。低速格斗机依靠小转弯半径与滚转响应，追猎机按闭合速度选择尾追或侧前切入，截击机和俯冲机用有限加力形成通过速度与脱离距离。轰炸机保持横穿路线，护卫机保持对编队锚点的行为，飞艇与气球使用各自低速包线。高速俯冲的策划意图由加速、攻击航线和脱离表现实现。

### 碰撞和结算

对投射物和目标在同一模拟步内的相对运动做扫掠，按接触先后处理多个目标和部件分区。用随构型变化的机身、翼段和挂载覆盖定义整机受击轮廓。仍附着的禁用部件保留覆盖，脱落后重算对应区域。命中事件携带真实世界接触点。投射物离机时采样局部锚点的世界位置，后续弹体按自身轨迹推进，空战命中沿用 XZ 平面。

将部件剩余生命之和作为整机生命读数。一次结算先统一处理伤害修正，再优先扣有生命的命中部件并等额分配余量。禁用或无分区命中直接等额分配，余量从已归零部件流向仍有生命的部件。穿透、爆炸、接触和持续伤害按各自触发规则调用同一结算。维修和改装同步更新生命读数及构型，普通维修保留已脱落状态。用同一份结算结果生成禁用、脱落和击毁事件，删除逐部件丢弃溢出伤害及重复扣血的分支。

### 内容和反馈

把同一份局部锚点定义和纯坐标转换放在模拟与表现可共用的边界。3D 模块提供机体、部件、场景物件及投射物网格工厂，按内容 ID 与参数缓存共享几何、底材和纹理。每个节点仅持有自己的姿态、材质变化和资源租用记录。常用构型复用资源，离场和改装负责解除对应引用，避免动态构型缓存随局数增长。

用纯数据事件把成功开火、接触、损伤升级、脱落和击毁从固定步交给特效、音频与 HUD。事件携带发生时的世界姿态、部件或挂点、命中方向与速度，让目标在帧内离场时仍能正确生成效果。使用特效 profile 组合外发光爆点、光晕、外发光火花、普通烟雾和碎屑。局部混合保留写实外观和深度关系，画质下降时降低次要粒子密度并保留爆点。命中烟团短暂停在接触处再随风漂移，持续损伤的发射器跟随机身，离体碎屑继承当时速度后下坠。枪口和命中音频按事件类别节流。

2D 模块复用现有图标和布局，应用层给战斗 HUD 提供显示数据与投影结果。按稳定实体 ID 复用高频雷达点、边缘提示和名牌。计量条、按钮、反馈列表和弹窗通过可复用组件调用。用仓库级指导链接项目 skill 和主规格，让后续内容任务先检查现有目录、挂点、profile、池和组件。

## Risks / Trade-offs

- 提高相对速度会缩短射击窗口。用同一种子验证直飞咬尾、加力脱离、急转反制、Boom and Zoom 和轰炸机横穿，再按时代调校武器窗口与提前量。
- 机翼外形与碰撞可能因滚转、改装或脱落出现偏差。用共用的局部定义检查翼尖、空隙、断翼和滚转枪口，避免用大圆填满机翼与机身之间的空域。
- 连发事件可能超过粒子、音频或 HUD 预算。优先保留枪口、有效命中和关键损毁反馈，缩减次要特效并以当前满额战斗预算验收。

## Migration Plan

在同一次变更内替换旧的运行时分支、坐标公式与受击闪白。完成正式入口和回归验收后随常规构建发布。现有存档格式沿用，无需数据迁移。
