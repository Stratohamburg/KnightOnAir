# Proposal

## Why

现有主规格已描述共享飞行、整机受击与运行时内容库。游戏中的敌机仍会按距离改写速度上限，禁用部件会从投射物命中查询中消失，枪口、烟雾与机体姿态也缺少统一的坐标来源。

## What Changes

- 让玩家、空中敌人和回放实体使用同一飞行控制规则。按时代调校敌机速度和转弯包线，实现短时咬尾、高速掠袭与脱离、低速格斗和路线横穿。
- **BREAKING** 以整机轮廓判定受击，部件分区提供损伤归因。击中仍挂在机体的禁用部件、未命中分区、或伤害超出部件生命时，按统一规则将伤害分配给剩余部件。
- 以真实枪口的外发光爆点、外发光粒子、可读弹道和分级音效表现开火与命中。命中烟雾先留在命中位置再漂移消散。严重损伤从部件锚点持续发烟，可脱落部件飞散下坠。整机受击闪白从反馈中移除。
- 用 3D 内容、特效和 2D 内容三个模块承接现有创建路径。共享几何和材质，隔离实例状态，复用高频粒子和 HUD 节点，并将项目 skill 用于后续扩展。

## Capabilities

### New Capabilities

本次沿用现有能力路径。

### Modified Capabilities

- `battle/air-combat-behavior` 规定同等输入下的飞行一致性、短时咬尾和高速脱离的验收条件。
- `battle/aircraft-damage` 明确受击后的分配、附着禁用部件与已脱落部件的处理，以及生命的唯一计算依据。
- `battle/weapons-targeting-and-bombing` 明确相对运动扫掠的接触点、枪口与弹道的坐标交接，以及写实外发光命中反馈。
- `rendering/procedural-aircraft` 明确锚点跟随与离体效果的边界，禁止整机受击闪白。
- `rendering/runtime-content-library` 明确三个模块的生产调用、图形资源所有权与单次事件分发。

## Impact

影响飞行控制器、遭遇导演、时代机体配置、扫掠检测、伤害与维修结算、战斗事件、程序化机模、特效批次、音频和战斗 HUD。战斗逻辑和渲染内部接口直接收敛到新实现。空战继续使用 XZ 平面玩法与三维表现，沿用现有锁定、投弹和路线规则。
