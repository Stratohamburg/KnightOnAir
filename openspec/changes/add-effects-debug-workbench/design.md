# Design

## Context

现有 `src/main.ts` 将原型直达入口交给 `ReferenceApp`。原型档案与可用机型各有目录，档案中有机型映射。特效参数分布于 `profiles.ts` 等内容定义，飞行效果通过 `AircraftFlightEffects` 使用模型上的部位，`CombatEffects` 消费战斗事件。调试台可直接复用这些路径。[调试台行为与验收场景](../../specs/app/debug-workbench/spec.md)

## Goals / Non-Goals

实现只读的调试工具。界面持有选择与播放会话，内容配置由所属库维护。参数编辑、配置写回和实战环境搭建均在本变更范围之外。

## Decisions

1. **沿用原型入口。** 在现有校验页面外层管理两个常驻页签，让原型内部三视图和模型选择保留各自含义。两页按档案映射传递机型 ID。缺少映射时显示空状态，保留原选择。离开页签冻结其时钟，返回时接续，退出则释放整个会话。
2. **由内容库描述可预览项。** 从机型、挂载和效果定义派生目录。在相应定义旁补充缺少的触发条件、显示名称和预设参数。按播放方式复用触发逻辑，例如为持续气流提供移动参考点，为命中提供测试表面。翼流带宽、透明度与真实挂点始终在运行时按 ID 解析。这样新增同类变体无需更新页面。
3. **创建独立预览空间。** 仅在进入特效页时创建相机、光照及当前预览需要的对象。整机调用飞机工厂，单项使用最小触发物。使用现有资源租约和特效批次。检查加载记录可确认预览没有构造战斗渲染器、关卡、地形、云海和 HUD。
4. **用固定步输入重现飞行。** 将航迹选择转换为方向输入，将动力选择转换为油门和加力输入，交给现有飞行动力学处理。每一步先结算姿态与部件状态，再更新模型、挂点与效果。重播时重建初态、重置随机源，并以相同步号重放预设切换、开火及损伤事件。慢放只改变固定步的播放速率。
5. **把停止、重置和换机分别处理。** 停止发射后，旧粒子继续按寿命演化。重置清除效果历史和孔洞。换机时释放旧实例及其租约。切换类别单显只改变可见性，可在同一时刻核对翼中宽带和翼尖细线。

## Risks / Trade-offs

- 特效可能只在战斗事件中取得速度、倾侧或局部命中姿态。预览应从当前模型、固定步状态和真实挂载构造同格式的事件，用倾侧齐射和同翼双洞验证坐标。
- 两个页签各自推进时间会导致切回时错过观察帧。活动页签独占更新循环，暂停时同时冻结飞机和效果，重复进入退出时检查循环、实例和资源租约。
- 将所有机型求值后再列目录会提前加载模型。使用库中的纯数据枚举条目，仅选中后创建实例。

## Migration Plan

通过现有展台调试入口接入，保留原型直达与指定机型链接。用相同库配置运行现有原型、机型特效和战斗特效测试，再按主规格走查两个预览。需要回退界面时，可将「校验」恢复为直接打开原型视图，调试会话没有需要迁移的存档。
