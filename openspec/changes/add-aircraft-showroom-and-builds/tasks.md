# 实施任务

## 1. 构筑规则与提质卡

- [x] 1.1 提取以机型与当前构型判定候选资格、安装结果与实际差值的共用逻辑。用现有时代、挂点、前置、互斥、重复上限和三选一回归场景验证。
- [x] 1.2 增加普通整机射速卡，沿用整机伤害倍率。用六个满状态炮位分别比较一张、两张及先提速后装枪的有效射速与弹着伤害，并验证禁用枪位继续停火。
- [x] 1.3 接入同座双联、增压、持续散热、快速回充、稳定投放与快转炮座。分别观察双枪口、加力持续时间、恢复秒数、稳定圈与炮塔跟踪，并验证卡面所列作用范围。
- [x] 1.4 按设计逐项整理现有 23 张卡的类别、时代效果、适用分支与视觉。逐层对照实际构型，覆盖重复强化、原有雷达、无弹舱、短翼耐久和火箭弹数。

## 2. 构筑中的结构扩建

- [x] 2.1 为单侧翼段、外置动力舱和侧射尾舱定义连接端、部件与发射点。验证同侧两次接长、对侧补装、尾翼后移以及受损或脱落时的火力和碰撞区域。
- [x] 2.2 用共享机体工厂绘制翼段、支柱、尾侧窗和枪口。用双翼机、三翼机及重型机核对正常战斗镜头下可辨的轮廓和开火位置。
- [x] 2.3 补齐串列弹舱、浮筒托架、飞艇炮廊及翼尖发射轨的候选、模型和发射点。按设计的 17 架机型逐架检查合法路径，观察各专属结构和投放效果。

## 3. 机库导航与独立展厅

- [x] 3.1 将主界面底部最右侧的预留按钮 `reservedB` 接入展厅，验证它位于第五项且第四项仍为预留。验证上方约三分之二为居中展示区，下方约三分之一为操作区，操作区包含切换机体弹窗、当前生效卡序和独立滚动的强化卡列表。在竖屏触摸和桌面鼠标下验证环绕、俯仰、列表滚动、完整取景及返回。
- [x] 3.2 从战斗配置枚举机型，展厅读取构筑规则返回的合法候选与安装结果，接入有序卡列、前后差异、撤销和重置。验证 A+B 撤销到 A 再改 A+C 的轮廓和属性，切机恢复原装，浏览未解锁机型后下一局仍用原装备机。只变更战斗配置，重新载入验证机型增删、卡牌资格和倍率传到展厅，并通过试射核对变更后的枪口位置与射击间隔。
- [x] 3.3 接入一次点击的挂点试射，验证各炮位从真实锚点播放展示事件并保留射界方向、射击间隔和枪口位置。确认试射不创建敌机、目标、锁定、战斗弹体、命中或奖励状态。
- [x] 3.4 处理试射重播、组卡中断、切机、退场与资源回收。反复操作后核对展示特效池和资源租约回到基线，存档的金币、装备、解锁及战绩无额外写入。

## 4. 展厅与正式空战集成验收

- [x] 4.1 按展厅“复现实战构型”场景，用 MASTODON 在局内选取左翼机枪段两次、尾段侧射舱一次、普通射速卡一次，再在展厅复现同卡序。逐项比对六处挂点、受击区、射速和枪口位置，确认展厅不引入战斗目标或奖励状态。
- [x] 4.2 按构筑“六炮位非对称重机”场景，在正常战斗镜头驾驶该机与敌机交战，记录偏翼长尾、不同射界接敌、损毁一个外翼枪位后其他炮位持续开火；在低画质和手机尺寸复核辨识度，并通过项目测试和构建。
