# Design

## Context

现有升级流程由 `World.openUpgrades()` 生成候选，`World.chooseUpgrade()` 直接调用安装逻辑并恢复战斗。模拟时间在升级阶段冻结，渲染器仍以战斗模式绘制飞机。升级数据目前使用字符串 `cost` 和少量 `max` 限制，翼段中心线已经支持插入段累加，但武器容量仍主要来自基础硬点数量。

本变更需要同时调整模拟交易、展示预览、战斗相机、底部 UI、事件反馈和构型容量。现有 `Part`、`RuntimeWeapon`、中心线布局、飞机工厂、内容目录和战斗事件作为共同边界继续使用。

## Goals / Non-Goals

**Goals:**

- 将升级选择、预览和确认安装拆成可验证的状态转换。
- 在不改变正式模拟构型的情况下展示候选升级的结构和数值结果。
- 让升级镜头从当前战斗构图连续放大，完成后连续缩回，并按边缘部件调整焦点。
- 让结构扩建类升级最多叠加十层，并使新增翼段、武器、碰撞和损伤身份保持独立。
- 使用本局金币进行原子支付，避免重复确认造成重复扣款或部分安装。
- 复用 `ContentCatalog`、飞机工厂、中心线挂点和有界特效池。

**Non-Goals:**

- 不把局内改装保存为下一局的永久构型。
- 不改变局外装备页和展厅的升级职责。
- 不把纯模式替换型升级自动变成十个相同挂点。
- 不新增网络服务、远程存档或外部媒体资源。

## Decisions

### 1. Use a two-phase upgrade transaction

升级状态包含 `selectedUpgradeId` 和展示预览状态。候选点击只更新这两个状态，正式 `Player`、金币、升级次数和战斗阶段保持不变。确认动作重新检查候选合法性、升级次数和金币余额，然后在一次提交中应用构型、扣款、消费次数并发出安装事件。

采用交易式提交可以避免预览失败后回滚复杂的部件生命、武器冷却和损伤状态。选中候选可以重复预览，确认失败时仍停留在升级状态。

确认前可通过「返回战斗」恢复空战或轰炸。候选及顺序保留至下次打开，玩家可以继续拾取金币。结束预览时释放展示副本，确认安装后消费升级次数并清空候选。

替代方案是先调用正式 `installUpgrade()` 再在取消时回滚。该方案会复制和恢复部件、武器、统计、伤害和中心线关系，容易在十层扩建时产生半提交状态，因此不采用。

### 2. Separate additive stack limits from unique modifiers

升级数据增加独立价格和结构叠加信息。数量增长类升级使用 `stackLimit`，默认值为 10，并允许机体配置覆盖。翼段、弹舱、侧射舱、发动机、散热件、装甲层和其他新增结构都按该规则统计已安装次数。真正的挂点模式替换或行为修改继续使用互斥和合法前置条件。

`left_wing_segment` 和 `right_wing_segment` 的结构长度显式设为 1 米。已安装扩建段的 `capacityContribution` 汇总到武器容量，基础 `hardpoints` 只提供初始容量。中心线的 `lineExtension()` 继续负责翼展、放置、碰撞轮廓和镜头边界的累积。

替代方案是把所有现有 `max` 直接改成 10。这样会让同座双联和炮塔快转座等模式修改重复作用在同一挂点，无法表达“新增结构可以扩建，模式修改仍然单次”的差异，因此不采用。

### 3. Build a presentation-only preview actor

预览使用当前玩家姿态和一个构型副本生成展示飞机。构型副本复用安装规则产生部件、武器和中心线位置，但不写回模拟 `Player`。正式玩家飞机和预览飞机各自持有实例资源租约，候选切换、确认和关闭时释放旧预览。

预览 actor 需要提供受影响部件的局部边界和目标姿态。相机使用这些边界计算升级焦点，部件动画直接读取中心线和局部锚点，避免为 UI 预览增加第二套空间规则。

替代方案是把候选部件叠加到正式飞机节点上。该方案会让渲染状态与模拟状态分叉，且正式构型重建时难以保证资源释放，因此不采用。

### 4. Keep simulation time frozen while presentation time continues

`World` 继续使用现有升级阶段冻结固定步进。`Renderer` 和升级动画使用独立的展示时间增量，使相机过渡、部件缩放、外移、回弹和屏幕抖动在冻结战斗时仍然播放。确认事件在安装动画开始时提交，世界保持升级阶段直到动画完成，再恢复进入升级前的阶段。

### 5. Add a continuous upgrade camera target

战斗相机保留进入升级前的巡航或轰炸目标，增加升级目标距离、注视点和飞机包围范围。升级开始时使用插值从当前构图过渡到目标构图。候选切换时只更新目标边界，不重置插值。大型飞机按当前翼展和机身长度降低额外放大，边缘部件可以允许部分越过视口边界。

升级托盘由 DOM 覆盖在画面底部，相机目标会把飞机和预览部件安排在上方三分之二区域。相机只改变展示视角，不改变模拟的 heading、bank、位置或投射物轨迹。

### 6. Emit one public installation event

确认成功后，世界发出一个包含升级 ID、部件 ID、武器挂点、安装姿态和动画类型的 `upgrade_installed` 事件。HUD、音频、触觉、相机抖动和三维动画分别消费事件。事件消费不修改金币、生命、武器或飞行阶段。

连续十段安装仍然使用事件和有界动画实例。短生命周期冲击效果进入现有对象池，部件和武器使用共享几何、材质和独立实例状态。

## Risks / Trade-offs

- **[Risk]** 展示副本可能与正式构型的统计或中心线位置不一致。**Mitigation** 让预览和正式提交共用同一个纯构型应用函数，并用固定种子测试两者的部件 ID、武器挂点和统计结果。
- **[Risk]** 十层翼段会扩大碰撞轮廓、武器数量和特效工作量。**Mitigation** 使用机体叠加上限、动态武器容量、有界池和低质量降级，保留十段的验收覆盖。
- **[Risk]** 升级相机在窄屏和大型飞机上可能遮挡部件。**Mitigation** 使用候选部件边界计算焦点，允许大型机体部分出框，并在 360×640、390×844、430×932 和桌面宽屏进行验收。
- **[Risk]** 快速重复点击可能造成重复支付或重复安装。**Mitigation** 确认动作使用一次性提交门控，提交期间禁用候选和确认控件，世界再次校验候选、余额和升级次数。
- **[Risk]** 候选切换频繁创建预览实例。**Mitigation** 复用共享资源，释放旧实例租约，并为候选切换和反复出击增加内容目录资源计数测试。

## Migration Plan

1. 为升级配置增加价格、叠加上限、结构长度和扩建容量字段，旧的描述型 `cost` 保留作为卡面文案。
2. 将现有结构增长类 `max: 1` 和 `max: 2` 迁移到十层叠加规则，将模式修改型升级保留为单次语义。
3. 先实现模拟交易和公开事件，再接入展示副本、升级相机和底部托盘。
4. 更新模拟、输入、镜头、移动端 UI 和内容目录测试。
5. 如果安装动画或预览出现问题，可以关闭升级入口并回退到确认前的正式玩家构型。局外存档不包含局内构型，因此无需存档迁移。

## Open Questions

无。价格使用本局金币，预览只影响展示，结构增长类升级默认十层，福克 Dr.I 左右翼首版各支持十段，这些决策已经在探索阶段确认。
