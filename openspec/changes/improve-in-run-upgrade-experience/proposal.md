# Proposal

## Why

局内升级目前会在点击候选时立即安装，升级弹层也会遮住整个战斗画面，玩家看不到飞机在战斗中的连续改造过程。现有 `max`、`refitLimit()` 和基础硬点容量还会过早限制新增翼段、武器、发动机和其他结构件，无法支持局内后期把飞机持续扩建到面目全非这一核心玩法。

这次变更把升级变成一个可观察、可确认、可支付并且能够持续叠加的战斗阶段。玩家可以在保持战场上下文的情况下预览改造，确认后支付本局金币，再让新增部件无缝并入正在飞行的飞机。

## What Changes

- **BREAKING** 将局内升级流程拆成候选选择、展示预览和确认安装三个阶段。点击候选只保持高亮并生成展示预览，确认按钮成功后才写入模拟构型、扣除金币和消费升级次数。
- **BREAKING** 将升级弹层改为从底部向上弹出的全屏宽度托盘，占用屏幕下方三分之一。三个候选纵向排列，选中项旁显示确认安装，金币不足时显示余额差额并禁止确认。
- 确认前可选择「返回战斗」，保留升级次数与当前候选，继续收集金币后再打开。
- 在升级状态保留上方三分之二的战斗画面和 HUD。当前飞机从正常战斗构图连续放大到升级构图，升级完成后连续缩回。飞机已经很大时使用较小的放大幅度，并允许模型超出视口边缘。
- 当待安装部件靠近画面边缘时，升级构图平滑移动注视点并调整距离，使部件获得足够的可见区域。升级前后的空战或轰炸视角语义继续保留。
- 为每项升级增加独立数值价格。价格从本局金币中支付，确认成功后扣除。升级预览期间不改变正式模拟构型和损伤状态。
- 增加升级部件的连续安装表现。部件从小比例出现，沿实际挂点或中心线移动到机体，再放大、回弹并完成定位。翼段和机身延长件需要先外移再冲击式伸展。
- 增加升级安装事件驱动的音效、触觉反馈、短促屏幕抖动、局部高亮和新增武器挂点确认。
- **BREAKING** 将数量增长类升级的叠加上限改为每架机体可配置，默认值提升到 10。福克 Dr.I 首版至少支持左翼和右翼各 10 个独立扩建段。
- **BREAKING** 移除左右翼段当前的 `max: 2` 限制。每次安装都新增一个独立翼段、独立武器、独立生命状态和独立挂点，翼展、碰撞、重量、操控和火力按安装次数持续累积。
- **BREAKING** 调整 `refitLimit()` 和 `weaponCapacity()` 对数量增长类升级的限制。基础硬点数量不再阻止扩建段继续提供新的武器容量，扩建能力由机体和升级的叠加上限配置决定。
- 将结构扩建、翼段、侧射舱、弹舱、发动机、散热件、装甲层和其他累计数值类升级的显式数量限制提升到 10。真正的互斥替换型升级继续遵守互斥关系和合法前置条件。
- 当前需要清理的显式数量限制包括 `left_wing_segment`、`right_wing_segment` 和 `tail_side_bay` 的 `max: 2`，以及 `radiator`、`cooling_loop`、`stable_bomb_rack`、`serial_bomb_bay`、`float_pylon`、`airship_gun_gallery` 和 `wingtip_rail` 的 `max: 1`。这些会新增结构件、武器或可叠加系统效果的升级改为默认最多 10 层，并允许机体覆盖该值。
- `twin_mount` 和 `turret_fast_traverse` 属于同一挂点的模式或行为修改，不因结构扩建提量而重复创建同一挂点。它们继续由互斥、前置和合法性规则控制，除非后续规格明确把它们改成可累计效果。
- 当前的 `refitLimit()` 会对福克 Dr.I 返回 1，并会按硬点数量和时代 headroom 限制其他未显式配置升级。当前的 `weaponCapacity()` 以基础 `hardpoints` 加少数特殊扩建计算容量。这两个全局门槛需要改为识别数量增长类升级，并使用机体的可配置叠加上限和已安装扩建段计算容量。
- 让展示预览和正式构型共用现有飞机工厂、中心线布局、挂点解析和 `ContentCatalog` 资源租约。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `battle/aircraft-refit`: 增加选择与确认分离、展示预览、金币支付、连续安装动画、可配置叠加上限和持续扩建构型。
- `battle/in-run-progression`: 规定升级次数和本局金币在确认安装后消费，并增加价格不足时的确认门控。
- `battle/session-lifecycle`: 规定升级预览和安装动画期间冻结战斗模拟，完成后恢复进入升级前的战斗阶段。
- `battle/camera-and-view-feedback`: 增加升级期间的连续放大、缩回、边缘部件构图和超出视口容许规则。
- `battle/battle-hud-and-event-feedback`: 增加金币价格、支付状态、升级安装事件、音效、触觉、抖动和部件定位反馈。
- `battle/input-and-action-binding`: 增加候选选择和确认安装动作，保持升级期间对飞行与轰炸输入的屏蔽。
- `rendering/runtime-content-library`: 约束展示预览、动态部件和安装特效继续使用共享资源目录与租约生命周期。

## Impact

涉及 `src/data/upgrades.ts`、`src/simulation/RefitRules.ts`、`src/simulation/World.ts`、`src/simulation/types.ts`、`src/content/2d/ModalViews.ts`、`src/app/GameApp.ts`、`src/styles/modals.css`、`src/styles/battle.css`、`src/rendering/BattleCamera.ts`、`src/rendering/Renderer.ts`、音频与特效服务，以及相关升级、镜头、输入和移动端界面测试。

需要新增升级价格、叠加上限、展示预览状态和安装事件的数据契约。现有中心线布局和部件挂点可以继续作为结构扩建、碰撞轮廓、武器绑定与动画路径的共同来源。

提案默认使用本局 `World.coins` 作为支付余额，结算时仍由现有存档流程汇总局外货币。升级预览不提前改变正式模拟状态，确认成功后才提交一次构型变更。
