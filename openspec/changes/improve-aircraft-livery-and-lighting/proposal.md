# 飞机涂装与云野光感统一

## Why

当前飞机虽然已经有 `color` 和 `accent` 字段，但渲染阶段主要把它们当作单一基色使用，机翼、机身和尾段缺少可辨识的色带、面板层次与材质变化，机体在机库和战斗画面中容易呈现为一块平涂色。飞机材质还使用独立的固定方向光，只接收云内雾化的 `cloudVeil`，没有共享云层的太阳方向、云影和冷暖反弹光，因此飞机的光感与已有云层脱节。需要先固定一套可配置、无贴图依赖、适合移动端俯视战斗的涂装与受光契约，再进入实现。

## What Changes

- 为可玩机体和 NPC 机体增加由稳定内容 ID 引用的涂装描述，至少包含主色、次色、饰边色、面板明暗范围和图案模式。现有机型继续提供兼容的基础颜色，缺少新描述时由目录校验报告缺口。
- 将涂装应用到机体工厂、机库预览、战斗玩家机和 NPC 批处理的同一套 3D 内容路径。涂装状态按实例隔离，几何、基础材质和图案参数仍通过 `ContentCatalog` 共享。
- 增加程序化涂装层次，在不引入外部贴图的前提下表达机身色带、翼面分区、饰边、面板轻微色差和低面数结构边缘。损伤、发热、部件高亮和云内覆盖继续叠加在涂装之后。
- 让飞机材质共享云层的太阳方向、云影采样和环境色板，形成暖色受光顶面、清晰冷蓝或淡紫阴影、柔和天空反弹和受控边缘光。飞机进入云层时保留轮廓可读性，云内包裹只作用于局部颜色和轮廓光。
- 统一机库与战斗的受光基线，覆盖固定俯视镜头、展厅观察、战斗姿态、滚转和不同时代色板。飞机受光需要随世界位置和姿态变化，并与地表云影的推进保持一致。
- 增加涂装与光感的开发验收信息，能够查看当前机体的涂装 ID、共享材质数量、实例材质状态、云影受光开关和低质量档降级结果。
- 保持模拟层、飞行手感、武器数值、机体几何证据、锚点语义和战斗事件协议不变。实现阶段不得为涂装引入运行时纹理下载或逐帧创建材质。

### Modified Capabilities

- `rendering/procedural-aircraft`: 增加数据驱动涂装、程序化面板层次、云野风格飞机受光、机库与战斗一致性及 360×640 可读性要求。
- `rendering/runtime-content-library`: 增加涂装内容 ID、共享材质参数、实例动态状态隔离和内容目录生命周期要求。
- `rendering/quality-and-performance`: 增加飞机材质与涂装在标准档的绘制、材质和低质量降级预算约束。

## Impact

涉及 `src/data/aircrafts.ts`、机型涂装配置与校验、`src/content/3d/AircraftFactory.ts`、`src/content/3d/NpcAircraftBatch.ts`、各机型装配器、`src/rendering/ShaderMaterials.ts`、`src/rendering/Renderer.ts`、云层共享受光 uniform 与开发诊断。需要补充机库预览、战斗固定镜头、NPC 批处理、滚转和云影移动的验收场景与渲染回归测试。预计不增加外部资源依赖，沿用现有程序化几何、云影贴图和内容目录。
