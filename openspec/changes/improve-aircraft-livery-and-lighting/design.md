# Design

## Context

当前飞机由 `ProceduralAircraft` 通过 `ContentCatalog` 租用共享几何和基础材质，各机型装配器把 `frame.color`、`frame.accent` 或部件专属颜色传给 `aircraftMaterial`。该材质已有损伤、发热、高亮和云内包裹状态，但太阳方向写死在片段着色器中，飞机没有直接读取 `Cloudscape` 的云影采样状态。NPC 还会把多个部件合并到 `NpcAircraftBatch`，因此涂装参数需要在合批后仍保持逐部件可区分。

云层已经维护太阳方向、时代色板、云影贴图和云内密度。地形材质通过共享的云影与飞机阴影 uniform 获得冷暖变化。新设计沿用这些数据源，把飞机纳入同一套世界受光语义，同时不把 Three.js 对象写入机型配置，也不让模拟层依赖渲染状态。

## Goals / Non-Goals

**Goals:**

- 为所有可玩机体和 NPC 提供可校验、可复用、无外部贴图依赖的涂装描述。
- 在固定俯视战斗镜头和机库观察中形成主色、次色、饰边与面板层次。
- 让飞机的暖色受光、冷色云影、天空反弹、边缘光和云内包裹与现有云层保持一致。
- 保持共享资源租约、实例损伤状态和 NPC 合批的独立性。
- 在标准档满战斗预算内完成，并为省电档提供明确的图案和采样降级。

**Non-Goals:**

- 不引入图片纹理、外部模型、网络资源或新的渲染后处理链。
- 不改变机体几何、飞行模拟、碰撞、武器或损伤规则。
- 不把涂装选择扩展为新的局外装备玩法或存档字段。
- 不重写云层的密度场、遮挡协议或地形色板。

## Decisions

### 1. 用稳定涂装目录承载颜色与图案参数

新增纯数据涂装描述和按 ID 索引的目录。描述包含主色、次色、饰边色、图案模式、色带位置、面板变化强度和低质量细节级别。机型通过 `liveryId` 引用，现有只有 `color` 与 `accent` 的机型由确定性的默认映射补齐。配置校验在模型生成前检查 ID 和必需字段。

选择目录而不是在 shader 中按机型 ID 分支，是为了让机库、战斗和 NPC 使用同一份内容，并避免每增加一架飞机就复制材质逻辑。选择程序化参数而不是贴图，是为了保留当前无贴图资源管线和移动端内存预算。

### 2. 将涂装分层留在飞机材质中

`aircraftMaterial` 保留共享基础材质，通过主色、次色、饰边和图案参数生成颜色分区。顶点阶段同时传出局部坐标、世界坐标和法线。片段阶段按局部纵向站位、横向归一化位置和确定性低频噪声生成色带、翼面分区与轻微面板变化，再叠加损伤、发热和部件高亮。

颜色分区使用平滑阈值和有限频率，避免条纹在远距离闪烁。部件专属材料仍可覆盖颜色参数，但不改变同一实例的动态状态引用。NPC 合批通过每个 piece 的涂装参数数组保留部件差异，避免把所有部件压成统一白色材质。

### 3. 共享只读环境受光，动态状态按实例保存

渲染器维护一组飞机环境受光 uniform，引用云层提供的太阳方向、时代色板和云影采样 uniform。`ProceduralAircraft` 创建或重建后，将这组引用绑定到其材质和 NPC 合批材质。每帧只更新太阳方向、云影中心、云影强度、云内包裹和质量级别，不新建材质或纹理。

片段受光采用包裹漫反射和冷暖混合。太阳方向决定暖色受光，天空色板提供低强度反弹，云影函数控制整体光照衰减，视角边缘保留受控的云野轮廓光。云内包裹只混合局部云色并限制最大强度，保证玩家覆盖层和飞机轮廓清晰。

选择共享 uniform 引用而不是复制每架飞机的 uniform 值，是为了让云影移动与多个飞机同步，并减少每帧更新的对象数量。选择在 `ProceduralAircraft` 提供显式环境受光入口，是为了避免把 `Renderer` 或云层对象下沉到 3D 模型装配器。

### 4. 机库与战斗复用同一工厂和涂装解析

机库预览、战斗玩家机和空中敌机继续通过同一 `ProceduralAircraft` 与模型注册表创建。涂装解析发生在工厂边界，装配器只请求 `partRoot`、`partPaint` 或 `paint` 得到已解析的材质。切换视图只改变相机、姿态和展示时钟，不另行定义颜色规则。

### 5. 以质量级别控制图案与受光细节

标准档保留完整色带、面板低频变化、云影和柔和边缘光。省电档使用相同涂装颜色和主色带，仅关闭面板噪声、降低边缘光和云内包裹采样。高档可以增加一次低频面板变化，但不增加纹理或无界对象。质量级别通过材质 uniform 或实例参数下发，避免重建飞机资源。

### 6. 诊断记录内容 ID 与共享状态

开发诊断增加当前玩家和活动 NPC 的涂装 ID、共享材质数量、活动实例数量、环境受光启用状态和质量级别。资源统计沿用 `ContentCatalog.stats`，不增加生产环境公开 UI。环境验收固定覆盖机库、战斗、滚转、云影移动和省电档。

## Risks / Trade-offs

- [风险] 程序化色带依赖不同机型的局部坐标，个别特殊构型可能出现色带位置不理想 → 允许每个涂装描述提供归一化站位和方向参数，并在机型校验台检查默认视图。
- [风险] 云影 uniform 在玩家覆盖层和世界场景中的坐标来源不同，可能出现受光滞后 → 统一由渲染器在完成云层更新后下发同一帧的环境状态，并在固定云影移动场景中比对。
- [风险] NPC 合批增加逐部件参数数组后可能提高 uniform 上传成本 → 参数数组容量绑定现有批次部件上限，省电档关闭面板细节并保留主次色。
- [风险] 冷色阴影过强会让深色机体失去轮廓 → 使用下限亮度和局部轮廓光，验收同时覆盖紫色、绿色、灰色和浅色机体。
- [风险] 旧机型默认映射导致颜色变化超出玩家预期 → 默认映射只从已有 `color` 与 `accent` 派生，保留旧主色并将新层次限制为低强度。

## Migration Plan

1. 先加入涂装数据类型、目录、默认映射和配置校验，不改变现有机体生成路径。
2. 扩展飞机材质参数与环境受光入口，接入云层太阳方向、云影和时代色板，并让 NPC 批处理保留逐部件涂装参数。
3. 为已登记可玩机体补齐涂装 ID，逐架检查机库、战斗和云影移动的固定视图。
4. 加入标准档、省电档和资源稳定性验收，确认绘制、三角形、材质租约和五分钟切换场景满足现行预算。
5. 若视觉回归或性能回归无法修复，回滚涂装目录引用和材质分层入口，保留旧 `color`/`accent` 映射与原有几何和模拟行为。
