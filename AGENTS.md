# KnightOnAir repository guidance

Read [README.md](README.md) and [docs/README.md](docs/README.md) for product overview, target platform, and design index before planning or modifying features.

When analyzing, tuning, or verifying combat, read the [air combat experience](docs/GAMEPLAY_DESIGN.md#空战体验) and the relevant OpenSpec scenarios. Use the intended player experience to identify related gaps in the same encounter, even when the report names a single symptom. For air combat, verify the aircraft and player input in question, then check how the two pilots gain or lose an advantage. Report related findings and keep edits within the requested scope.

Player controls, NPC flight and replay inputs advance through the fixed-step simulation in `src/simulation`. Keep Three.js objects and DOM nodes at the presentation boundary. Implement changes using the current runtime content definitions and the affected OpenSpec scenarios. [Runtime content library spec](openspec/specs/rendering/runtime-content-library/spec.md) · [Runtime content library skill](.agents/skills/runtime-content-library/SKILL.md)

- Look up aircraft, parts, mounts and weapons by their configured IDs. Use `ContentCatalog` leases for shared geometry, materials and textures. Release each instance's leases when it leaves the scene. [Combatants](src/data/combatants.ts) · [Weapons](src/data/weapons.ts) · [3D catalog](src/content/3d/ContentCatalog.ts)
- Use the existing local anchors for parts, muzzles and engine outlets. Resolve them with the actor's heading and bank. Use the aircraft factory for both battle and hangar models and the scene factories for projectiles and reusable objects. [Anchors](src/content/3d/anchors.ts) · [Aircraft factory](src/content/3d/AircraftFactory.ts) · [Scene objects](src/content/3d/SceneObjects.ts)
- Enemy aircraft must reference an existing, usable, era-appropriate 3D model from the prototype workbench by its registered aircraft ID and load it through the same aircraft factory and model registry as the player. Reuse its existing geometry and part layout. Do not invent aircraft, build NPC-only substitute models, or use generic or cross-era fallback geometry. Leave aircraft that lack a suitable model out of the spawn pool. [Aircraft model registry](src/content/3d/aircraftModels.ts) · [Era aircraft assignments](src/data/eraEnemies.ts)
- Check left-right symmetry from independently measured source contours when preparing a new aircraft's three-view plate. Record the drawing tolerance and obtain the user's decision on any confirmed asymmetry before finalizing the plate or generating a model. [Aircraft reference pipeline](.agents/skills/aircraft-reference-pipeline/SKILL.md) · [Procedural aircraft spec](openspec/specs/rendering/procedural-aircraft/spec.md)
- Extend the weapon effect profiles and reuse the existing effect batches. Combat events carry the source or impact pose, and effect instances own their smoke, flash and debris lifetimes. [Effect profiles](src/content/fx/profiles.ts) · [Effects](src/content/fx/CombatEffects.ts) · [Effect batches](src/content/fx/EffectBatch.ts)
- Pass display data to the HUD and use existing meters, buttons, dialogs, icons and node pools. Keep combat and navigation actions in the application. [Combat HUD](src/content/2d/CombatHud.ts) · [Battle status](src/content/2d/BattleStatus.ts) · [Components](src/content/2d/components.ts) · [Icons](src/content/2d/icons.ts)
- When adding or changing pages, first-level navigation, second-level tabs, menu copy, shop, activities or the debug showroom, read the [UI navigation specification](docs/UI_NAVIGATION_SPEC.md) and apply the [ui-navigation-system skill](.agents/skills/ui-navigation-system/SKILL.md). Keep the OpenSpec contract, product documentation, route/view implementation, styles and tests synchronized.
