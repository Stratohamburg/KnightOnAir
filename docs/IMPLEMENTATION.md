## 实现选择

- 采用总设计中固定 `cameraYaw = 0` 的相机，摇杆向上始终对应屏幕向上。系统分文档里的随航向绕转示例与此不一致，因此没有采用绕机旋转。
- 空战主平面用 XZ；Y 仅参与空间表现、落弹与分层。模型本地 +Z 为机头。
- 固定相机看向 +Z，屏幕向右对应世界 −X。触控与键盘在输入输出时统一转换，修复左右反向；摇杆帽保持跟随手指，飞机保留转向惯性。
- 战斗相机距离从 32 调至 39，并直接读取 `RULES.camera.distance`，避免配置与实际镜头不一致。
- 参考本机 MadMax 的 `src/input/joystick.ts` 与圆环反馈设计：虚线半油门圈、实线满油门圈、金色满油门状态、加速进度环及百分比。满油门行程按实际圆环半径映射，触控与键盘共用反馈；轰炸微调和能量耗尽显示实际限制。
- 常规敌机模型放大至初始 Swift 相当或更大，碰撞半径随之调整；侦察/追猎/护卫的转向上限降为 80/90/85°/秒，转向采用渐进角速度，俯冲攻击机保留受加速响应约束的直线冲刺。
- `FlightDynamics.ts` 用协调转弯关系 `ω = −g·tan(bank)/v` 耦合倾角和航向，用推力储备、翼载与质量计算可用载荷，再以 `acos(1/n)` 得到倾角上限；滚转惯量随 `mass·span²` 增长，角速度受阻尼与速率限制。87.5° 是避免奇异值的数值保护。此为面向游戏手感调校的简化模型；基础质量、翼面积、改装附加质量、动力和翼面损伤都参与计算。
- 四种机体在装备页均可预览；预览不写装备。解锁分数是当前数据基线，可以在 `aircrafts.ts` 中调整。
- Swift 和 Wasp 也携带基础小型重力炸弹，保证默认机体能体验 M2；Courier 和 Mastodon 的装填、稳定性与重型载荷形成差别。
- 商店与两个预留页保留设计要求的可返回占位内容。
- 省电/标准/高档位使用简化投影阴影，不启用昂贵的实时阴影贴图。三档分别从 0.70 / 0.85 / 1.00 分辨率比例起步，低帧率持续三秒时下调；下限 0.55，持续流畅后逐步恢复到所选档位。
- 维修、弹药与冷却选项可重复抽取，避免后期不足三个合法选项；重复的弹药/冷却模块复用已有挂点，避免实体持续叠加。
- 所有战斗音效由 Web Audio 合成；浏览器尚未允许播放时可正常静音游玩。

## 自动化验证

`npm test` 运行 39 项行为测试：

- 真实触控事件与键盘的上下左右、触控四个斜向：用战斗相机投影验证模型机头和飞行速度与屏幕输入方向一致；取消触控后释放捕获并复位摇杆帽。
- 半油门与满油门的行程/百分比/进度环一致，松手清零、轰炸油门限制、能量不足提示。
- 轻型机深度侧倾、重型机浅侧倾；弱动力、发动机损伤、巨型翼改装降低操控包线；协调转弯、左右内倾、松杆回正与反向滚转连续。
- 六类空中敌人的转向惯性、转速上限和有限状态。
- 输入与航向的延迟响应、松杆巡航和能量恢复。
- 30 / 60 / 120 渲染帧率下相同的固定步长结果。
- 升级期间玩家、敌人、弹道、金币、风场、准心、冷却与时钟暂停。
- 暂停恢复不产生时间追赶；升级结束恢复先前的轰炸模式。
- 锁定、丢失、按秒衰减、新目标重新积累和制导发射。
- 高速投射物扫掠碰撞。
- 轰炸稳定门槛、冷却、投弹后不可变落点与地面伤害。
- 发动机减效、武器挂点失效、坠毁到结算。
- 经验溢出、合法互斥池、三选一、次数扣减、后期通用选项。
- 大型/轻型/不对称构筑对参数、可视部件和碰撞分区的影响。
- 维修、存档恢复、装备合法性、解锁、损坏数据和存储不可用降级。
- 四架机体分别运行 300 秒，自动驾驶、升级与投弹，检查状态数值有限、池容量受限、活动实体小于 250，且战斗和成长持续发生。

耐久测试为验证所有阶段，将玩家设为免伤；死亡另由专门的测试验证。这不是五分钟生存难度或真机帧率的证明。

`npm run build` 同时执行严格 TypeScript 检查与生产打包。Three.js 作为独立共享包；打包器对约 503 KB 的 Three.js 文件给出体积提示，其 gzip 约 130 KB。

## 浏览器验收步骤

体积云、草浪和树木风动有独立的开发验收场景。固定场景操作、三档配置和包含 14 个敌人及 140 枚弹道的帧统计见[体积云与风动植被](IMPLEMENTATION_0_4_TERRAIN_CLOUD.md#体积云与风动植被)。

1. 默认进入出击页，观察朝上飞行的飞机、地面和云层；打开五个导航入口。
2. 装备页浏览四架飞机，点击部位高亮；预览未解锁飞机后返回出击，确认实际装备没有变化。
3. 出击进入第一关；单指拖动、超出摇杆边界、第二手指点击、触控取消、松手与旋转屏幕。
4. 收集经验，打开升级，确认战场暂停；选择一项后检查部件、次数与操控变化。
5. 开启轰炸，松杆等待绿色准心，投弹后观察落点、冷却和命中反馈。
6. 暂停、帮助和设置；修改画质，恢复飞行；失焦后确认必须手动继续。
7. 主动结束飞行或生命归零，查看结算；重试或返回机库；刷新后确认存档恢复。
8. 在 360×640、390×844、430×932 与桌面宽屏检查布局、触控区和横向溢出。

真实手机的 30/60 FPS 目标、连续五分钟的真实触控操作、设备发热与电量、iOS/Android 浏览器兼容性仍需要目标硬件实测。M4 的完整内容调优、性能矩阵和可访问性专项测试属于后续工作。

- 360×640、390×844、430×932 和 1280×900：主界面、装备页、三选一面板及控制区无横向溢出；360×640 的三个升级选项均处于可见范围。
