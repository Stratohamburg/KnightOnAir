# 界面信息架构与菜单规范

本文档定义 KnightOnAir 的局外页面职责、一级和二级菜单规则、界面文案边界以及菜单变更的同步路径。

## 规范层级

界面行为按以下顺序维护，越靠前的文件越接近行为真源。

1. [OpenSpec 主规格](../openspec/specs/app/navigation-and-menu-architecture/spec.md) 定义必须满足的行为和验收场景。
2. 本文档定义产品信息架构、页面职责、按钮和文字。
3. [ui-navigation-system skill](../.agents/skills/ui-navigation-system/SKILL.md) 定义实现或评审菜单变更时的工作流程。
4. `src/content/2d/` 与 `src/app/GameApp.ts` 承载视图和路由实现，`src/styles/` 承载视觉规则。

行为发生变化时先更新 OpenSpec，再更新本文档和 skill，最后修改实现与测试。单纯修正错别字时可以只修改本文档和对应的实现文案，但需要检查 skill 中的术语表。

## 产品信息架构

```text
局外机库
├── 出击（一级菜单）
│   └── 选关（二级弹窗，战役关卡与四时代自由巡航）
├── 装备（一级菜单）
│   ├── 时代（二级分段）
│   ├── 机体（二级横向选择）
│   ├── 部位（二级芯片）
│   └── 升级（二级面板）
├── 商店（一级菜单）
│   ├── 抽奖（二级分段）
│   └── 货币直购（二级分段）
├── 活动（一级菜单，预留）
└── 展台（一级菜单，调试入口）

战斗
├── 暂停（二级弹窗）
├── 局内改装（底部托盘）
└── 设置/帮助（二级弹窗）
```

战斗、结算和局外机库是应用状态，不属于同一组一级菜单。战斗中的暂停、升级选择、设置和帮助是覆盖层，不能加入局外底部导航。

「局内改装」托盘占用战斗视口底部三分之一。三张候选卡只切换预览，选中项显示「确认安装」和支付状态。「返回战斗」关闭托盘并保留升级次数与候选。键盘可按 U 打开，使用 Tab 与 Enter 操作，关闭后焦点返回可用的战斗控件。[改装输入规则](../openspec/changes/improve-in-run-upgrade-experience/specs/battle/input-and-action-binding/spec.md)

## 一级菜单

一级菜单是玩家在局外跨职责移动的固定入口。移动端底部导航最多保留五个槽位，始终只有一个选中项。除调试入口外，一级菜单的顺序和名称在同一版本内保持稳定。

| 产品名称 | 当前路由 ID | 面向对象 | 页面职责 | 当前实现状态 |
| --- | --- | --- | --- | --- |
| 出击 | `sortie` | 所有玩家 | 查看副本信息并开始下一局 | 已实现 |
| 装备 | `equipment` | 所有玩家 | 选择载具、查看数据、管理局外升级和出击配置 | 已实现，升级入口需要向此页收敛 |
| 商店 | `shop` | 所有玩家 | 抽奖和货币直购 | 当前为占位页 |
| 活动 | 未来替换 `reservedA` | 所有玩家 | 活动列表、活动规则、任务进度和奖励领取 | 预留槽位 |
| 展台 | `showroom` | 开发和测试人员 | 检查机体、强化构型、武器试射和视觉校验 | 已实现，必须按调试入口管理 |

### 一级菜单通用规则

- 一级菜单只表达跨页面职责。筛选、排序、时代、构型和视图模式都放在对应页面的二级控件中。
- 每个一级页面必须能回到出击页。页面内的返回按钮使用“返回出击”，浏览器历史和 hash 路由也要回到同一状态。
- 一级菜单切换时，不得隐式改变当前装备、存档、货币、活动进度或副本选择。需要提交的动作必须由明确按钮完成。
- 未开放功能使用“预留”或“即将开放”状态。预留页只说明用途和返回路径，不展示会被误认为已可用的购买、领取或解锁按钮。
- 调试入口不能影响玩家存档和下一局出击配置。生产构建隐藏展台，开发构建或显式调试入口才显示展台。
- 一级菜单名称使用两个到四个汉字。名称变更时同步更新路由 ID 对照表、导航按钮、页面标题、无障碍标签、hash 兼容逻辑和测试。

### 当前实现的兼容映射

`reservedA` 保留活动槽位。`#showroom` 打开展台，旧链接 `#reservedB` 指向同一调试页面。开发构建显示展台。生产构建可用 `?debug=1#showroom` 显式进入。

## 页面职责与内容

### 出击页

出击页是局外默认页，主内容区只围绕当前副本做出击决策。当前装备只保留一行紧凑确认信息，不展开载具数据，不在出击页编辑载具、部位或升级。

应该有的内容如下。

- 副本编号和名称。
- 副本所属时代、战役或自由巡航类型。
- 任务目标和简短 briefing。
- 本局固定装备或当前装备标识，仅用于确认出击对象。
- 环境提示，例如天气和时段。
- 当前副本最高分。
- 未来可插入的活动入口、关卡奖励和首通奖励区域。未实现时不显示空卡片，不占用主要行动区。

应该有的按钮如下。

| 按钮文字 | 层级 | 行为 |
| --- | --- | --- |
| 选关 | 二级入口 | 查看战役通关、解锁状态和四时代自由巡航，选择后返回简报 |
| 更换 | 二级入口 | 跳转装备页并保留当前副本选择 |
| 飞行指南 | 覆盖层入口 | 打开帮助弹窗，不离开出击页 |
| 出击 | 页面主按钮 | 使用当前副本和已确认装备创建一局战斗 |
| 设置 | 全局工具 | 打开设置覆盖层 |

出击页不放置载具属性网格、武器构型编辑、抽奖、货币充值、局外升级、部位编辑、展台校验和开发工具按钮。副本奖励未来加入时使用副本信息下方的独立区域，领取动作只在结算或奖励可领取状态下出现。

推荐文案使用“出击”“选关”“当前装备”“任务目标”“环境”。避免使用“开始游戏”“购买”“强化一次”等会混淆页面职责的文字。

### 当前实现的收敛项

以下项目是当前代码与目标职责之间的已知差异，后续实现菜单或页面改造时按本规范收敛。

| 当前实现 | 目标收敛 |
| --- | --- |
| `renderEquipmentBody` 已有载具、部位和数据，但没有局外升级面板 | 将局外升级、消耗、前后数值和确认动作放进装备页二级面板 |
| `shop` 是通用占位页 | 按抽奖和货币直购两个二级分段实现 |
| `reservedA` 显示为“预留” | 活动上线后替换显示名和职责，保留旧路由兼容 |

### 装备页

装备页承载载具选择、载具数据、部位信息、武器构型和局外升级。它是玩家准备下一局构型的唯一常规入口。

应该有的内容如下。

- 当前预览载具和当前已装备载具的明确状态区分。
- 时代标签和同年代载具横向选择。
- 生命、极速、加速、转向、能量、翼展、受弹面积和挂点等对比数据。
- 主要武器和构型摘要。
- 机头、左右翼、机身、机背、机腹、机尾等部位选择。
- 所选部位的功能、挂点和损伤影响说明。
- 升级入口及升级后的前后数值、消耗、限制和撤销条件。

应该有的按钮如下。

| 按钮文字 | 层级 | 行为 |
| --- | --- | --- |
| 时代名称 | 二级分段 | 切换载具时代，保留当前页面位置 |
| 载具名称 | 二级横向选择 | 切换预览，不立即装备 |
| 上一架 / 下一架 | 二级辅助 | 在当前时代循环浏览载具 |
| 部位名称 | 二级芯片 | 高亮模型部位并更新说明，不重绘整页 |
| 装备此机体 | 页面提交 | 只对已解锁载具生效，确认后更新下一局装备 |
| 升级 | 二级入口 | 打开局外升级面板 |
| 应用升级 / 确认 | 二级提交 | 提交升级并更新构型和数据 |
| 返回出击 | 页面返回 | 返回出击页，不因浏览预览而改变装备 |

“预览”“已解锁”“当前装备”“升级”四种状态必须可区分。浏览未解锁载具只允许查看允许展示的信息，不能通过点击卡片或返回页面隐式装备。

### 商店页

商店只处理经济系统中的获取和购买。它不承担载具选择、部位升级、战斗升级或活动任务。

商店的二级分段固定为“抽奖”和“货币直购”。

抽奖区域应该包含奖池说明、概率或规则入口、抽取次数、消耗货币、剩余货币和结果反馈。按钮使用“抽取一次”“十连抽”或由奖池配置提供的明确次数文字。抽取前必须在同一操作上下文显示消耗和确认状态。

货币直购区域应该包含商品包名称、获得货币、价格、购买限制和已购买状态。按钮使用“购买”“确认购买”或“已购买”。购买完成后只更新货币和商店商品状态，不直接改变当前装备。

商店不显示副本 briefing、载具部位编辑、开发校验、关卡奖励领取和战斗升级候选。

### 活动页（预留）

活动页是未来的玩家内容入口。它可以承载活动卡片、活动规则、任务进度、活动兑换和奖励领取。活动的有效期、完成条件和领取状态必须在卡片或详情页明确显示。

活动页不能复用商店的购买按钮语义，也不能把限时奖励伪装成关卡奖励。活动未上线时保留槽位和返回路径，页面只显示“活动即将开放”及用途说明。

### 展台

展台是调试界面，服务于模型、构型、武器和表现验收。它不属于玩家成长循环，不读取或写入玩家的局外装备结果。

当前展台工具条包括“换机”“撤销”“重置”“试射”“校验”和“返回”。这些按钮的职责如下。

- “换机”只改变展台预览载具。
- “撤销”只移除最近一次展台强化。
- “重置”恢复原装构型并清空展台强化列表。
- “试射”创建预览射击，不推进战斗、不扣货币、不写入统计。
- “校验”进入调试台，默认打开「原型」。顶部常驻「原型」「特效」页签。「特效」下可选择「特效库」或「机型表现」。内容目录、配置来源与切换行为见[调试台主规格](../openspec/specs/app/debug-workbench/spec.md)。
- “返回”回到出击页。

校验台可通过 `?reference=1` 或 `#reference` 直接打开。带 `frame` 的链接按原型 ID、机型 ID 或已有别名选中原型。从展台进入时通过「返回展台」回到展台。原型的三视图、资料与模型工具留在原型页，效果配置和模拟输入从共享库读取，播放状态属于当前预览会话。

展台可以使用强化卡列表和构型统计，但所有字段都必须标注为预览或调试语义。新增展台工具必须说明调试目的、输入状态、输出状态和销毁路径，不能把展台按钮复制到出击或装备页面。

## 二级菜单与切换栏规则

二级菜单只在当前一级页面内切换同一职责下的视图或操作集合。每个切换栏只解决一个维度。

- 时代切换只筛选载具，不同时改变部位、升级或装备状态。
- 机体列表只改变预览对象，不直接提交装备。
- 部位芯片只改变高亮和说明，保留当前构型。
- 装备页的升级面板只处理升级候选、消耗、前后数值和确认。
- 商店分段只在抽奖和货币直购之间切换。
- 展台工具条是动作按钮集合，不伪装成玩家导航切换栏。
- 二级切换栏最多一层。需要继续细分时使用列表、弹窗或详情面板，不在切换栏中嵌套切换栏。
- 同一切换栏的选项必须互斥、同类、可见状态一致。选中态使用 `aria-selected` 或 `aria-pressed`，并同步键盘焦点和视觉状态。
- 切换预览类控件不提交持久化状态。提交类按钮必须使用动作词，并在成功或失败后提供明确反馈。
- 局部更新必须保留滚动位置、焦点和当前筛选。不得因切换一个芯片或升级卡而销毁整个页面容器。

## 层级、按钮和文字规范

### 层级判断

使用以下判断决定控件放在哪一层。

1. 是否跨页面移动。是则使用一级菜单。
2. 是否只改变当前页面的同类视图。是则使用二级切换或列表。
3. 是否提交、购买、装备、领取或开始战斗。使用动作按钮，并明确结果。
4. 是否显示规则、帮助、详情或确认。使用覆盖层，不新增一级菜单。
5. 是否仅用于开发调试。放入展台或开发工具入口，生产构建隐藏。

### 文案

- 一级菜单使用“出击、装备、商店、活动、展台”这组产品名。路由 ID 可以保持稳定，但显示文字不能与职责冲突。
- 页面主按钮使用单一动作词或动作短语，例如“出击”“装备此机体”“抽取一次”“购买”。
- 返回动作统一使用“返回出击”或上下文明确的“返回展台”，不使用含义不清的“关闭”代替页面返回。
- 状态文字使用“当前装备、已解锁、未解锁、即将开放、可领取、已领取、已购买”。
- 数值单位与数据来源保持一致。比较数据必须同时显示比较对象或前后状态。
- 文字最小字号遵循移动端 UI 规范，关键数值使用等宽数字。按钮热区可以大于视觉尺寸，但不能与相邻高频控件重叠。

| `openspec/specs/app/navigation-and-menu-architecture/spec.md` | 界面职责、菜单层级、状态转换、验收场景 |
| `openspec/specs/app/out-of-battle-hangar/spec.md`、`shell-routing/spec.md` | 机库入口、页面生命周期、返回路径和覆盖层 |
| `openspec/specs/app/persistence-and-meta-progression/spec.md`、`battle/in-run-progression/spec.md` | 装备、升级、货币、奖励和存档影响 |
| `docs/UI_NAVIGATION_SPEC.md` | 信息架构、职责、按钮、文案、当前实现映射 |
| `.agents/skills/ui-navigation-system/SKILL.md` | 变更流程、术语和回溯清单 |
| `src/content/2d/HangarView.ts` | 一级菜单 ID、显示名、图标、底部导航、出击和装备视图 |
| `src/content/2d/ShowroomView.ts` | 展台调试工具条和调试文案 |
| `src/content/2d/ModalViews.ts` | 二级弹窗、设置、帮助、选关和升级文字 |

| `src/styles/hangar.css`、`showroom.css`、`modals.css`、`base.css` | 导航高度、按钮层级、切换栏和热区 |
| `tests/mobile-ui.test.ts`、`tests/aircraft-showroom.test.ts`、相关 OpenSpec 场景 | 页面入口、按钮行为、局部更新、调试隔离和返回路径 |
| `docs/README.md`、`AGENTS.md` | 规范索引和协作入口 |

变更完成前至少搜索以下关键词，确认没有遗留旧名称或旧职责。

```text
reservedB
showroom
shop
equipment
sortie
活动
展厅

```

如果菜单变更需要新增经济、活动、奖励或持久化字段，还要同步对应的 OpenSpec 主规格和存档规则。不要只修改导航按钮文字。
