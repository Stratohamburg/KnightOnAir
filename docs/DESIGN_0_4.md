## 单一战斗管线与敌人行为

战斗实体都经过同一条模拟管线。

```text
玩家输入 / 空中 AI / 网络输入
        ↓
空中目标方向 / 速度意图
        ↓
空中编队与分离
        ↓
空中 ControlDamage 包线与 integrateAirActor
        ├── 地面/水面路线与独立移动积分器
        └── 共享武器挂点、弹道、部件命中、伤害分流和事件
```

敌人行为只决定目标意图。`chase` 追击玩家，`patrol` 沿路线巡逻，`intercept` 预测玩家位置并切入，`escort` 保持长机编队，`dive`、`crossing`、`standoff` 和 `convoy` 分别表达俯冲、横切、远距和车队路线。它们都使用同一套避让、部件命中、损毁性能衰减和武器失效。敌人受损后保留原行为，只有在该行为无法继续完成时转入 `flee` 或 `breaking`。行为分类、配置字段和目标点规则见 [敌人与武器配置](changes/12-enemy-weapon-config.md)，共享部件和损毁接口见 [部件与损毁](changes/03-parts-and-damage-degradation.md)。

## 补给与构筑

小修理包和大修理包都恢复总生命。总生命由机身段、机翼、发动机、尾部、炸弹舱和武器挂点的部件生命相加得到。小修理包恢复总生命上限的 12%，大修理包恢复 28%，修复额度按机身段、发动机、机翼、尾部、炸弹舱、武器和雷达的固定优先级填充部件缺口。部件不会脱落，生命归零后保持在机体上并进入损毁状态，后续命中会穿过该部件命中后方部件。满修理包拾取改给 2、5 金币，不给经验。首次刷新在 8–12 秒，常规间隔 18–26 秒，场上合计最多 3 个。精英击毁掉落同一套大修理包，不再设置独立的精英补给类型。[补给细则](changes/01-air-pickups-and-upgrade-pool.md)

去掉 `repair`、相应权重与安装效果。按时代、前置、互斥和剩余挂点筛选后，仍须提供三个不同且可安装的选项。`ammo`、`cooler`、`armor_belt` 作为通用兜底。原案的 `max: 999` 有耗尽边界，若承诺无尽局始终三选一，这三项应定义为可无限重复的数值升级，复用已有部件。装甲带提高生命上限时保留当前生命。例如核心 40/100，装甲带 +12 后应为 40/112。当前 `installUpgrade` 会把生命上限差额也加到当前生命，并在重复安装时复活部件，这两个分支需要分别处理。[升级安装与候选实现](../src/simulation/World.ts)

## 操控、损毁与投弹

- **双区油门。** 归一化有效行程达到 0.74 时普通油门已满。达到 0.84 取得加力许可，低于 0.76 撤销。实际加力比例在 0.84–1.00 间从零增至满值，只按实际加力耗能。回到普通油门即可回充，耗尽后须回充至少 8 点并释放加力输入才能再次点火。满加力极速和加速度分别以常规值的 1.55、1.9 倍试调。键盘方向键给普通油门，Shift 请求加力。轰炸时普通油门上限 45%，加力关闭。固定镜头下屏幕向右对应世界 −X，触控与键盘沿用同一方向转换。[输入基线](../src/input/VirtualStick.ts)
- **共享战斗管线。** 玩家、空中敌人、地面单位和水面单位都实现同一个 `CombatEntity` 部件接口。`hitEntity`、`applyPartDamage`、`evaluateDamage`、武器挂点失效和 `part_disabled` 事件各只有一套实现。空中玩家输入、空中敌人行为和未来网络输入产生目标方向或速度意图，并进入同一个 `ControlDamage`、分离和 `integrateAirActor`。地面与水面使用各自路线和移动积分器。所有层仍共用部件命中、总生命扣减、武器失效、弹道和事件。不能按 owner 类型复制两套计算。部件生命归零后保留在机体上并进入损毁状态，后续命中跳过该部件并继续检查后方部件。验证左右翼损毁镜像、单侧发动机失效后的可恢复转向，以及修理额度按优先级填充多个部件时的确定性。[部件与损毁细则](changes/03-parts-and-damage-degradation.md)
- **行为分类。** 敌人的行为由配置驱动。`chase` 追击玩家，`patrol` 沿路线巡逻，`intercept` 预测玩家未来位置并切入，`escort` 保持长机编队，`dive/crossing/standoff` 表达空中攻击段，`convoy` 表达地面或水面车队路线。行为只生成目标点或路线意图。空中目标进入分离和飞行积分器，地面与水面目标进入各自的路线移动积分器，之后统一接入开火、命中和伤害结算。损毁后的敌人保留原行为，无法完成任务时才进入 `flee` 或 `breaking`。
- **转弯与投弹坡度。** 沿用世界单位重力 4.905 和现有滚转符号。协调转弯的速率大小为 `g × |tan(bank)| / V`，同速同坡度的半径相同。机型差异来自可达坡度、速度和滚转响应。轰炸坡度由机型基准和左右升力、尾翼状态收紧，最终受当前飞行包线约束。完好轻型 Wasp 约 35°，重型 Mastodon 约 17°，受损只会收紧。目标倾角和积分后的实际倾角都须限幅。[飞行实现](../src/simulation/FlightDynamics.ts) · [投弹包线](changes/09-bombing-envelope-and-aero-turn.md)
- **瞄准与释放。** 准心在机体坐标内平滑，沿机头前方 4–14 单位、左右半角 10°。每步用当前航向换算世界落点，释放时复核最终落点仍在锥内、弹舱可用、稳定度达标且冷却完成。失败保留装填，成功则记录落点和释放高度。投出后飞机转弯、镜头切换或车辆移动均不会带动落点。[轰炸实现基线](../src/simulation/World.ts)

## 战场、告警与画面

| 系统 | 0.4 规则和验收 |
| --- | --- |
| 刷新与分离 | 全场最多 14 个活动敌人。空中普通 ≤7、精英 ≤1，地面与水面合计 ≤6。开场、整波、车队、召唤与排队重试均逐实体核算。各时代可下调预算。空中分离半径先取 7，生成点需兼顾机体尺寸。34–46 单位仅是候选距离，最终用当前视野和生成物范围检查是否在屏外。测试满额召唤、队列释放、极端宽高比和镜头过渡。 |
| 战斗反馈 | 移除敌方瞄准线、攻击预警文字及地面预警圈，保留模拟内的开火准备时间、玩家锁定反馈与投弹落点环。空中开火用 `enemy_fire`，地面火力用 `ground_attack`，对应方位在雷达上闪烁。屏外箭头最多 4 个，当前威胁优先。受击、部件损毁和击毁各按状态转换通知。每次 `World.frame` 内收集全部固定步事件，由 `GameApp` 在该帧结束时消费一次。测试一帧多个固定步、暂停后恢复及关闭音效时的视觉告警。 |
| 地表与路线 | 模拟和渲染共享随种子确定的地表采样。道路、铁路、水路提供路线位置和方向。车辆沿线行驶，同路保持车距，各车分别计入预算。移除 `aa`、`emplacement` 的数据及所有生成引用，保留无武装设施 `depot` 作为地面目标。验证跨地块接缝、路面贴合，以及车队经过时落在旧位置的炸弹按实际位置结算。 |
| 高度与镜头 | 以地表 +20 为玩家目标净空，敌机处于同带 ±4，命中沿用 XZ 和目标层。云层中心取地表 +14/+28/+42。固定 yaw。巡航距离 46、俯角 64°、FOV 48°，轰炸时用约 0.35 秒过渡到 50、74°、34°，注视点向准心偏移 55%。炸弹从释放位置落向地表，时长试取 1.4 秒。锁定环、弹道、地面标签与阴影统一按各自高度投影。 |
| 云与美术 | 云遮挡地面、敌机和敌方弹道。主场景完成后用同一相机绘制玩家、玩家弹道及瞄准信息，云后敌机名牌随可见性淡出。雷达保持方位信息，遮挡只影响显示。低档简化云形也须通过相同的遮挡测试。鲜艳低模以机翼、发动机和挂载轮廓区分构型，受损侧和威胁应在小屏上可辨。 |

## 实施顺序与验证

1. **先验证一局战斗。** 在现有四架机体上接入补给、升级兜底、双区油门、统一生成预算、开火事件与前向投弹。复用固定种子，在 30/60/120 Hz 渲染下比较模拟结果。回归末期三选一、零能量仍可普通加速、召唤满额和暂停恢复。
2. **再接部件和战场。** 用玩家、一架有双翼的敌机和一支车队验证命中、失效、反馈、掉落及地表。接入损伤坡度和相机后，在同一存档场景、同一视口对比同一车辆的像素宽度、准心位置及玩家可见性。原案的 1.35–1.45 倍放大作为调镜目标，须实际投影测量。
3. **最后扩画面和时代。** 在 360×640 竖屏以满额敌人、重装机、云层和双场景绘制跑五分钟。标准档以整帧合计 <150 次绘制、<150k 三角形（含云 <25k）为预算。分别记录设备、画质、实际渲染分辨率和帧时间，检查标准档中端设备 60 FPS、低端 30 FPS 目标。性能降级优先减少云和表现开销，战斗预算与命中结果独立于画质。之后按时代完成装配、存档及实战验证。[时代交付顺序](content/ERA_CONTENT_0_4.md)
