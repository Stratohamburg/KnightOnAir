# 0.4 时代内容、默认装配与存档迁移

本规范适用于 0.4 的内容录入和迁移。0.3.0 代码中有 4 架机体、11 种敌人（6 空中、5 地面）、11 种武器。提案 12 的“迁移 9 种敌人”指移除两种固定炮台后保留的条目数。战斗规则及实施顺序见 [0.4 战斗设计与方案评审](../DESIGN_0_4.md)。

## 四时代的可玩范围

时代顺序为萌芽期 → 一战 → 二战 → 初代喷气。机库按时代分组，每关从该时代的有效配置选择敌人、装备和升级。先补齐现有四机字段，再引入前三个时代各一架代表机，四时代即可逐一试玩。13–16 合计列出 23 架，其中 17 架属于基础名录（含现有四机），6 架为扩展候选。代表机通过验证后按时代扩充。

| 时代 | 代表机 / 基础名录 + 候选 | 首轮要验证的玩法 | 录入前需处理的差异 |
| --- | --- | --- | --- |
| 萌芽期 | `sparrow_05` / 3 + 1 | 低速双翼机、轻武器、首轮升级和空中补给。该时代只用目视武器，保留玩家识别威胁的方位提示。 | 13 使用了 12 标为一战的机枪和轻弹，列为萌芽期允许的变体。萌芽期不投放精英，90 秒触发器须服从本关配置。[萌芽期表](../changes/13-era-pioneer-config.md) |
| 一战 | `kestrel_08` / 5 + 1 | 双翼、三翼、浮筒与大型机轮廓。以通用机翼、发动机、武器叠装形成“利维坦流”，记录增加的挂点、质量与操控代价。 | `leviathan_12` 是名单中的飞艇，其他机体也可走重装流。水上机的早期鱼雷须配有可命中的目标和可用水路，纳入对应批次。[一战表](../changes/14-era-ww1-config.md) |
| 二战 | `falcon_13` / 5 + 2 | 单翼、双发重战、飞行艇、四发重轰。按车队与船队检验目标层筛选及挂点差异。 | 15 的地面/水面小标题写 8，实际有 10 行。表内的早期导弹车与时代边界有冲突，评审建议首轮先用移动防空车，导弹车留到喷气关。水上巡逻机每个状态只占一个名额。[二战表](../changes/15-era-ww2-config.md) |
| 初代喷气 | `swift_01` / 4 + 2 | 现有四机按旧装配出击，验证锁定、机背炮塔和投弹。再接入喷气时代的新装备。 | 16 的开局波次写了 `scout_line`，本时代敌人表未列 `scout`。启用前须显式加入合法变体，或换成由本时代已有敌人组成的开场编队。[喷气表](../changes/16-era-jet-config.md) |

0.4.0 已录入一期的 17 架机体。装备机体决定关卡，开场、普通波次、精英、增援和升级各自读取该时代的配置。一期机体随单局最高分解锁，v2 中已解锁的机体继续可用。二期候选仍保留在 13–16 的内容表中。

## 配置的读取与校验

- 机体 ID 跨版本稳定。数据声明基础部件、挂点、默认装配、时代、构型和重装容量。局内把安装位置绑定到实际部件，部件失效后按该绑定关闭武器。结构件可叠层时，同时更新外形、命中区、附加质量及可用挂点。`refit` 给出容量和收益，具体倍率由完好、受损与满载对照试玩确定。[机体配置提案](../changes/11-airframe-config-and-refit.md)
- 同一 `hunter` 在不同时代有不同生命和装配。以“基础 ID + 关卡时代”解析出唯一变体，保留基础 ID 用于行为和统计。时代表注明“实际”的数值直接作为最终值。无覆盖值的字段可从基础值乘一次时代系数。以萌芽期 `hunter` 生命 39 为例，载入后仍应为 39。
- 每个已启用的装配、编队、召唤和升级引用必须能解析到具体 ID。将表内“机枪”“重弹”等名称补成武器 ID，按挂点类型、尺寸、数量和允许目标层检查，平台炮塔的射界与单发散布分别配置。对跨时代早期型列出允许使用的时代与平台。水面单位占地面/水面共享预算，武器按其目标层判断能否命中。[敌人与武器配置提案](../changes/12-enemy-weapon-config.md)
- 对没有弹舱或默认炸弹的新机型，出击、HUD 和升级预览均须能处理空装配，投弹入口显示不可用。当前 `World.bombWeapon` 按机体炸弹 ID 取值，不能假定每架新机都有合法返回值。新弹种和行为在模拟、反馈和目标层都可用后再加入抽选池。[当前战斗实现](../../src/simulation/World.ts)

## 旧四机装配的兼容判据

机库预览、实际出击与部件失效都应使用同一套装配。迁移以 0.3.0 的机体表和 `World` 构造结果为准。11、16 的默认表均漏列了 Swift 和 Wasp 的 `lock_missile`。[机体数据](../../src/data/aircrafts.ts) · [装配实现](../../src/simulation/World.ts)

| 机体 ID | 迁移后首次出击应具备的能力 |
| --- | --- |
| `swift_01` | 机头双联机炮、锁定导弹、基础重力炸弹。 |
| `courier_02` | 双翼机枪各承担一半弹数，各自绑定翼部件，另有基础重力炸弹。 |
| `mastodon_03` | 四联机枪在两翼各发两弹，机背炮塔独立，弹舱装重型炸弹。按 16 的机头单挂点录入会改变受损后的火力。 |
| `wasp_04` | 轻型机炮、锁定导弹、基础重力炸弹，保留现有锁定时间修正 −0.25 秒。 |

## 新玩家起点与旧档

新玩家以 `sparrow_05` 为起始机的方案，随萌芽期可玩的代表机关卡一起交付。起始机用明确的 ID 或唯一的 `starter` 字段选取。四架喷气机的新解锁分 6000 / 6800 / 7600 / 8600 作为试玩曲线，发布值取决于从首局到各时代的实际解锁节奏。

当前实施直接启用存储键 `knight-on-air.v2`。旧的 `knight-on-air.v1` 和其他版本数据均视为无效，读取后初始化默认数据，不做权益迁移。v2 数据只接受版本号 2，写入失败时仍使用当前内存中的默认或已更新数据完成本次游玩。[现行存档实现](../../src/services/Save.ts)

验收覆盖新档、旧 v1 档直接重置、损坏 JSON 和存储写入失败。每个时代各用固定种子跑 3–5 分钟，核对开场、普通波次、增援、升级与投弹入口，再在真实解锁流程中核对装备和结算。
