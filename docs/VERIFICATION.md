## 地形海拔与视口景物验收

地形验收使用固定种子 491 和 360×640 视口。启动 `npm run dev` 后打开以下入口，并在控制台读取 `window.__koa.environment.report()` 与 `window.__koa.environment.terrainViews()`。

```text
/?environmentTest=terrain&view=lowland
/?environmentTest=terrain&view=valley
/?environmentTest=terrain&view=hill
/?environmentTest=terrain&view=highland
/?environmentTest=terrain&view=shore
/?environmentTest=terrain&view=shore&clouds=off&cloudShadows=off
/?environmentTest=terrain&view=bombing
```

每个镜头检查 `terrainViews().views` 返回的 `elevation`、`flowerWeight`、`wetlandWeight`、`rockWeight` 和 `shoreMask`，并检查 `terrainViews().structure` 的脊线覆盖、谷地覆盖和排水密度。确认当前视口出现与区域匹配的花甸、湿地植物、房屋、灌木、裸岩和水岸。调用 `environment.pause(true)` 后连续执行 `frame()`，地面颜色、景物位置与风动相位应保持不变，恢复后从同一相位继续。移动到 `x = TERRAIN.chunk` 附近后重新执行 `frame()`，跨块边界的高度、材质和景物位置应连续。

开发诊断中的 `terrain.visibleChunks`、`terrain.terrainTriangles`、`terrain.terrainDraws`、`terrain.houseInstances` 和 `terrain.scenicInstances` 用于记录地形预算。标准档完整战斗场景在 360×640 下总绘制次数低于 150 次、总三角形低于 150,000 个，省电档优先降低视口外景物密度与阴影。

同一份诊断还记录 `terrain.derivation.generationMs`、`thermalIterations`、`hydraulicIterations`、`cacheHits`、`cacheMisses`、`seamError`、`gullyQuality` 和 `sedimentWeight`。这些指标来自固定次数的生成期派生，飞行、暂停、恢复和轰炸落点不会启动每帧侵蚀。缓存不可用时使用结构化山脉骨架、谷地横截面、热侵蚀权重和低频残余噪波回退。

离线 GAN 与扩散候选使用 `node tools/procedural-terrain-research.mjs --model=<name> --candidate=<json>` 对照高程、坡度、曲率、脊线连续性、谷网密度、平铺接缝和资产成本。浏览器运行时不加载模型权重或执行推理。

地面颜色不再读取场景时间或风向形成连续移动波纹。分别推进 2 秒、改变风向、关闭云影并切换轰炸镜头，山脊、丘陵、谷地、草甸、花甸和裸岩边界应保持世界坐标锚定，近中景保持清晰通透。

## 浏览器手工验收步骤

1. 默认进入出击页，观察朝上飞行的飞机、地面和云层；切换底部导航入口。
2. 装备页浏览各时代机体，点击部位高亮；预览未解锁机体后返回出击，确认实际装备未改变。
3. 出击进入第一关；测试单指拖动、外圈加力、第二指点击、触控取消、松手回正与旋转屏幕。
4. 收集经验并打开改装，按下方的局内改装步骤检查预览、支付和安装。
5. 开启轰炸模式，松杆等待绿色准心，投弹后观察固定落点、冷却和命中反馈。
6. 打开暂停、帮助与设置，切换画质并恢复飞行；页面失焦后确认必须手动继续。
7. 主动返航或生命归零，检查结算、重试与返回机库；刷新页面确认 `localStorage` 存档恢复。
8. 在 `360×640`、`390×844`、`430×932` 与桌面宽屏下检查布局、触控安全区与横向溢出。

### 局内改装

1. 用 `npm run dev` 从出击页进入黎明草甸。在开发者工具 Console 执行 `const run = window.__koa.world; run.upgradesAvailable = 12; run.coins = 0;`。等改装按钮亮起后打开面板。
2. 分别在 `360×640`、`390×844`、`430×932` 和桌面宽屏检查。托盘贴合战斗视口底部，占高度三分之一，三项依次纵向排列。上方 HUD 与战场保持可见，打开时镜头连续拉近。
3. 在供弹和延长机枪段之间切换。确认当前选择的按压状态与不足差额同步变化，确认按钮处于禁用状态，正式机体、金币和可用次数保持原值。选中边缘翼段时观察镜头平移，新增段应位于托盘上方。
4. 选「返回战斗」，执行 `run.coins = 100;`，再次打开并核对候选和顺序。使用触控、鼠标或 Tab 与 Enter 选择翼段并确认。检查仅扣一次对应金币和一次升级机会，部件先外移再伸展和回弹，出现高亮、音效和短促抖动。动画结束后镜头连续缩回。另在轰炸模式重复此步骤，确认准心和方向恢复。
5. 验收同侧十段时，在每次打开托盘前使用下面的 Console 命令固定合法候选。每次从托盘选同一侧并确认。验收翼尖移动十米、增加十个各自可损伤的段和十个不同机枪挂点，`run.legalUpgradeOptions` 中该侧延长段达到上限后退出候选池。

   ```js
   const wing = run.legalUpgradeOptions.find(upgrade => upgrade.id === "left_wing_segment")
   run.choices = [wing, ...run.legalUpgradeOptions.filter(upgrade => upgrade !== wing).slice(0, 2)]
   ```

6. 多次往返切换相同候选，使用 `window.__koa.renderer.diagnostics` 比较同一构型的共享几何、材质和飞机实例计数。安装或返回战斗后，展示实例应释放。新增正式部件会增加正式实例的材质数量。

本地已安装 Chrome 和 Playwright 时，可在开发服务器运行期间执行 `node tests/browser/in-run-upgrades.cjs http://localhost:5173` 重跑四种视口。Playwright 安装在仓库外时，用 `KOA_PLAYWRIGHT` 指定其模块目录。

# 飞机涂装与云野光感验收

在 `http://localhost:5173/` 打开机库和出击页，分别检查三翼机、二战单翼机和喷气机。机库与战斗中应保持相同的主色、次色、饰边和色带规则。固定俯视战斗镜头下，飞机朝向太阳的面保持暖色明亮，背光面出现浅蓝或淡紫冷影，滚转时受光连续变化。

进入云影覆盖区域后，飞机整体受光平滑降低并保留涂装分区。进入云层时，局部云色包裹和轮廓光增强，机头方向、主次色和轮廓仍清晰。切换省电档后，面板细节和边缘光减少，主次色、饰边、云影明暗差异继续可辨认。

开发环境读取 `renderer.diagnostics.aircraft`，记录当前 `liveryId`、活动实例数量、实例材质数量、环境受光状态和 `liveryDetail`。标准档 360×640 满战斗验收继续使用低于 150 次绘制和 150,000 三角形的现行门槛。重复切换机库机体、进入战斗和退出战斗后，`renderer.diagnostics.content.shared` 中的资源数量在预热后保持有界。
