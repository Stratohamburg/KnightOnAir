## 1. 本轮要解决什么

当前版本已经具备完整可玩循环（机库 → 战斗 → 升级 → 轰炸 → 结算），但反馈集中在三处：

1. **节奏与资源**：能量在普通油门下持续消耗、维修靠升级抽卡、血瓶只在精英击毁时出现，导致续航依赖运气、衰减不可预期。
2. **战场可信度**：敌人直接刷在附近且数量无明确上限、相互重叠；敌人没有部件；地面单位追着玩家跑、没有地形起伏；云雾是几张平铺贴片，没有体积和遮挡关系。
3. **表达与风格**：敌方瞄准线和地面预警线过多；击毁与受损反馈不足；美术是低饱和写实向，时代混搭且没有从螺旋桨到喷气的演进感。

0.4 的方向是：**把“信息”和“代价”做清楚，把战场做成有地貌、有天气、有时代的 Q 版低模世界。**

## 4. 跨文档统一决策（所有文档必须遵守）

> 各主题文档可以细化这些决策，但**不得与之冲突**。若确需修改，先在本文档对应条目更新并注明影响面。

### D1 · 部件模型统一（对应文档 03）

- `Part` 从“玩家升级挂件”扩展为**玩家与敌人共用的运行时部件**，新增字段（示意）：

```ts
type PartRole = "core" | "wing" | "engine" | "tail" | "gun" | "bay" | "turret" | "float" | "radar";
interface Part {
  id: string; role: PartRole; side: -1 | 0 | 1;     // 左/中/右
  x: number; z: number; radius: number;            // 机体本地坐标，命中用
  health: number; maxHealth: number; destroyed: boolean;
  lift: number; thrust: number;                     // 该部件提供的升力/推力份额
  weaponIds: string[];                              // 该部件挂载的武器
  visual: { kind: string; scale: number; detachable: boolean };
}
```

- 敌人数据新增可选 `parts: PartRecipe[]`；没有配置的敌人自动生成 `core + 左右翼` 三件套，保证“所有敌人都有部件”且旧数据可迁移。
- 命中判定统一为“线段扫掠 vs 部件圆”，玩家沿用现有 `hitPlayer` 思路，敌人新增等价函数；核心生命归零即击毁，非核心部件按 `damageTransfer` 分流伤害。
- 视觉：部件随损毁变黑/冒烟/喷火/脱落；渲染层只读 `Part` 状态，不再自己推断。

### D2 · 损毁性能衰减模型（对应文档 03）

- 新增模拟层模块（建议 `src/simulation/DamageModel.ts`），输入部件状态，输出共享伤害结果和按层消费的**控制包线**。空中玩家和空中敌人共用飞行控制计算，地面与水面只消费其发动机、轮组、武器和核心状态：

```ts
interface ControlDamage {
  liftLeft: number; liftRight: number;        // 0..1
  rollAuthorityLeft: number; rollAuthorityRight: number; // 0..1
  thrustLeft: number; thrustRight: number;    // 0..1
  yawStability: number;                       // 0..1，尾翼/方向舵
  instability: number;                        // 0..1，滚转振荡幅度
  weaponFactor: number; lockFactor: number; bombFactor: number;
}
```

- **非对称滚转基线（以右翼全毁为例）**：向左滚转权限降到约 15%，左转能力约为正常的 35%；向右滚转权限保留约 90%，但叠加 0.2–0.3 rad、约 1.5–2 Hz 的滚转振荡，表现为“滚转一会大一会小”；同时存在向缺失翼侧的升力偏置与缓慢偏航漂移。左翼全毁镜像。
- 发动机损毁按左右推力份额形成偏航/滚转偏置；尾翼损毁放大 `instability`（航向摆动、回正变慢）；机头/武器损毁只影响火力与锁定；炸弹舱损毁禁止投弹。
- 衰减必须**分级可读**：单个普通升级/一次命中不得让飞机完全不可控；至少保留一个“能飞回去”的包线。所有系数放在 `src/data/config.ts` 或独立的 `damageTuning` 中。

### D3 · 敌人数量与避让（对应文档 02）

- 硬上限：空中 **8** 架（**含精英；非精英空中 ≤7**）、地面 **6** 台、全场活动敌人 **≤ 14**；召唤/增援同样受上限约束（当前 `scout` 召唤与 `elite` 生成可以绕过上限，必须修复）。
- 刷新节奏：空中每 **9–13 秒**一波，每波 **1–2 架**（120 秒后最多 3 架）；地面每 **10–14 秒 1 组**（06 落地后资源车队 2–3 辆算 1 组，仍受地面 ≤6 约束）；玩家生命低于 35% 时降低追击型权重。
- 避让：空中敌人之间维持 `separationRadius = 7`（可按半径缩放）的分离力，转向时把分离向量与目标方向加权混合，禁止重叠刷在同一格；地面单位在同一条路线上按固定车距排队。
- 刷新必须发生在**屏幕外**（距玩家 34–46），并在进入视野前给出边缘指示/雷达提示；不允许在玩家头顶直接出现。

### D4 · 双区油门与加力（对应文档 04）

- 摇杆行程归一化 `t ∈ [0,1]`，分三段：
  - **正常区** `0 ≤ t < 0.74`：油门 0–100%，**不消耗能量**，能量按正常速率恢复；拉到底只是普通满油门。
  - **迟滞带** `0.74 ≤ t < 0.84`：需要额外拉出一段距离才进入加力，防止误触；此时仍按正常满油门处理。
  - **加力区** `0.84 ≤ t ≤ 1`：加力等级 `boost = (t-0.84)/0.16`，进入阈值 0.84，退出阈值 0.76（迟滞）。
- 加力效果基线：极速 ×1.55、推力（加速度）×1.9；能量以约 `energyDrain` 的速率消耗；能量为 0 时无法进入加力，且需回充到 **8** 点以上才能再次触发。加力结束后速度以约 8/s 回落到常规极速。
- 轰炸模式下外圈加力区关闭，只保留 ≤45% 的微调油门；滚转上限不在本决策里写死，按 D12/09 的**机型 + 损伤动态包线**计算（重型机更小、受损后更小）。
- HUD：内圈=普通油门、外圈=加力区，加力时外圈与能量条变橙红；触觉在迟滞带给出一次轻振；键盘需要独立的加力键位（建议 `Shift`，长按生效）。
- 能量条语义从“加速燃料”改为“加力储备”；普通油门、普通转向、轰炸微调都不再扣能量。

### D5 · 战斗信息与事件总线（对应文档 05）

- **删除**所有敌方瞄准线/预警线绘制：`warningLines`（`Renderer`）与 `攻击预警` 文字标签移除；保留敌人开火前的内部 `warning` 计时（玩法需要），但表现改为雷达告警。
- `World` 新增只读事件队列 `events: WorldEvent[]`（每帧清空或按生命周期保留），事件至少包括：`enemy_fire`、`enemy_destroyed`、`part_destroyed`、`player_hit`、`missile_lock_warning`、`ground_attack`。`GameApp`/`Renderer` 只消费事件，不直接读敌人内部状态做提示。
- **事件命名权威表**以 05 §3.1 为准；02/03/06 提出的扩展事件（`wave_started`、`elite_incoming`、`enemy_spawn`、`enemy_recalled`、`spawn_dropped`、`elite_deferred`、`enemy_hit`、`pickup`）统一并入同一队列，命名以首次定义文档为准，实施时不得并存两套事件名（例如地面开火统一用 `ground_attack`，不再出现 `ground_fire`）。
- **雷达告警**：常驻小型雷达盘（玩家居中、半径 60 单位），敌人为光点；敌人开火瞬间对应方位的雷达扇区/光点闪烁 + 提示音 + 屏幕方向红色脉冲（无连线）。地面火力同理。
- **边缘指示**：屏幕边缘的安全区外画指向箭头，最多 4 个，带方位、距离与类型；开火中的敌人优先。镜头保持固定 yaw（不绕转），仅在必要时做 ≤8% 屏幕的视线偏移，避免破坏“上=前”的操作直觉。
- **击毁反馈**：命中标记、击毁信息条（类型 + 分数/掉落）、目标解体/爆炸/碎片、屏幕短促震动、音效与连击提示；部件击毁单独提示（如“右翼脱落”）。这些事件同时服务于 03 的部件脱落表现。

### D6 · 地面与地形（对应文档 06）

- 新增**确定性高度场** `terrainHeight(x, z)`，模拟层与渲染层共用；基准：可玩区起伏 **0–10 单位**、水面高度 **-1.5**、远景山体到 **18**；道路/水面对高度场做平整与压低。
- 地面分块流式加载：每块 64×64，近处 20×20 段（约 800 三角形），远处降级；9 块环绕玩家，确定性种子保证同位置同地形。
- 玩家/敌机**高度层**：视觉高度 = `terrainHeight + 20`（由 D13/10 定义，替代早期 +5），相机与弹道/炸弹/特效同步；不做撞地坠毁（竖屏单手操作不引入俯仰事故），地形接近时仅提示。
- 地面单位全部改为**沿固定路线移动**：路线是确定性折线/样条（道路网），单位按 1.2–2.2 单位/秒匀速行驶、按车距排队，不再追玩家；离开玩家 90 单位后回收。

### D12 · 投弹包线与真实气动转弯（对应文档 09，接口在 03/04）

- **真实协调转弯公式全模式通用**：`n = 1/cos φ`（载荷因数）、`ω = g·tan φ / V`、`R = V²/(g·tan φ)`，`g = 4.905` 世界单位/s²；同 bank、同速度下半径与质量无关（这是真实气动结论），机型差异来自**速度、最大坡度包线、滚转响应**三处。
- **投弹滚转包线按机型 + 损伤动态计算**：`baseDeg = clamp(14 + 1.15 × damageResponse, 14, 36)`（`damageResponse` 取 03 的 `flightEnvelope.response`，已含质量/翼展/惯性/推力/损伤）；再乘 `liftTailFactor = clamp(0.45 + 0.55×liftAvg×(0.75+0.25×yawStability), 0.35, 1)`；最终 `min(该值, 损伤后 maxBank, 36°)`。示意：完好 Wasp 34.7° / Swift 27.8° / Courier 19.6° / Mastodon 16.9°，右翼全毁后各降到约 60%–78%。
- **投弹滚转响应 ×0.75**：迟缓机进一步变迟缓；退出投弹立即恢复 03 的完整包线与响应。
- **前向目标约束**：瞄准点用机体本地坐标 `p + forward×forwardDist + right×lateral`；`forwardDist ∈ [4,14]`、`|lateral| ≤ tan(10°)×forwardDist`（基线，可调 6–12°）；`dropBomb` 要求 `dot(aim−p, forward) ≥ 2`，否则拒绝并提示“目标不在机头前方”。世界坐标 `aimOffset` 的旧实现废弃。
- **数值边界**：09 只定义投弹包线与目标规则；03 提供 `FlightEnvelope.maxBank/response` 与 `updateFlightTurn(..., bankLimit, bombing)` 的 clamp 语义；04 提供 45% 油门、能量与 HUD；08 的新机体通过现有质量/翼展/推力数据自动得到投弹坡度，可选 `Airframe.bombingBankLimitDeg` 手调。
