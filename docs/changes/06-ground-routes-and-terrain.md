## 1. 问题与现状

### 1.1 地形只是渲染层的“假高度”

地面目前是 **9 块完全水平的 `PlaneGeometry(64, 64, 22, 22)`**，在 `y = 0` 平铺：

- `src/rendering/Renderer.ts:89-96` — 创建一块 64×64、22×22 段的平面，复制到 9 个 `Mesh`，共享 `this.terrainMat`；`terrain` 数组见 `Renderer.ts:27`。
- `src/rendering/ShaderMaterials.ts:37-58` — `terrainMaterial()` 的顶点着色器在 GPU 里做了 **仅视觉的位移**：`float h = fbm(world.xz*.035)*1.7-1.2; world.y = h;`（`ShaderMaterials.ts:40-41`）。位移幅度只有约 `[-1.2, +0.5]`，且只存在于顶点着色器，**不回写几何体、不进入任何 CPU 状态**。
- 所谓道路与河流是片元着色器画出来的纹理（`ShaderMaterials.ts:45-48`）：道路是 `mod(p.x+p.y*.26, 28.)` 的条纹，河是 `abs(p.x - 12 - sin(...))` 的正弦带。它们不影响移动、生成、命中或任何模拟逻辑。
- 分块跟随只改 `mesh.position`（`Renderer.ts:445-473` 的 `updateTerrain`），块与块之间确实无缝，但那是“平地无缝”。

由此产生的真实问题：

| 问题 | 直接原因（定位） | 玩家看到的症状 |
| --- | --- | --- |
| 没有真实起伏 | 高度只在 shader 顶点里，`Renderer.ts:60-130`、`ShaderMaterials.ts:40-41` | 战场永远是一张平地，山脊/河谷/海岸不存在 |
| 单位与地面不对齐 | 地面单位渲染在 `y=-0.1`（`Renderer.ts:597`），假高度在 `[-1.2, +0.5]` 之间 | 车辆时而埋进土里、时而悬浮 |
| 森林/阴影悬浮 | 树 `y=0.1`（`Renderer.ts:457-472`），影子 `y=0.05`（`Renderer.ts:542`、`Renderer.ts:614-619`） | 树根悬空，阴影飘在地面上 |
| 相机与投影按平面处理 | 相机 `y = 3 + sin(62°)*39 ≈ 37.4` 固定（`Renderer.ts:497-510`）；`project()` 只接受一个任意 y（`Renderer.ts:798-808`） | 不会出现山体遮挡、从山脊后方掠过等空间关系 |
| 弹道/落点按平面处理 | 炸弹从 `y = 4*(1-t²)` 落到 0（`Renderer.ts:721-726`）；`updateBombing` 只在 XZ 平面结算爆炸（`World.ts:1305-1331`） | 落点、火焰、预警圈都贴在水平面上 |
| 水面缺失 | 模拟层没有水位/水面概念；河流只是 shader 条纹 | 08 的水上飞机/飞行艇无处可落（见 §1.3） |

`docs/systems/04-enemies-battlefield.md:82-99` 已经规划过 `GroundChunk`（高度、材质区域、道路、目标、风场采样），`docs/GAME_DESIGN.md:76-88` 也把“地面高度场 → 地面目标/道路/建筑/阴影”写进视觉层级，但 0.3.0 均未实现。本文是把这两处规划落地为可玩的系统。

### 1.2 地面单位在“追玩家”，固定炮台违背方向

- `Enemy` 只有 `layer: "air" | "ground"`（`src/simulation/types.ts:84-110`，`layer` 在 `:87`），没有路线、没有方向约束。
- `World.updateEnemies` 对**所有**单位先算 `target = Math.atan2(p.x - e.x, p.z - e.z)`（`World.ts:559`），只有 `layer === "air"` 的分支会改写朝向（`World.ts:560-588`）；地面单位从头到尾都在转向玩家。
- 地面单位的转向阻尼是 `5`，比空中单位的 `1.8` 更快（`World.ts:595-600`），速度 2.5–3.8（`src/data/enemies.ts:109-153`）——结果就是车辆以约 3–5.5 单位半径**原地绕圈“溜冰”**，而不是在路上行驶。
- 固定炮台：`aa` 防空炮速度 0（`enemies.ts:108`）、`emplacement` 机枪阵地速度 0（`enemies.ts:124-138`）；另有 `depot` 燃料设施速度 0（`enemies.ts:154-168`）。`aa` 与 `emplacement` 与 D6“移除固定炮台类单位”直接冲突。
- 生成：导演每 10 秒（30 秒后每 7 秒）在玩家航向 ±0.6 rad、距离 24–38 的位置直接放一个地面单位（`World.ts:477-492`），经常刷在视野里，且没有“从路口开过来”的过程。地面单位在 85 单位外被回收（`World.ts:675-677`），65 秒后强制回收。
- 开火：地面单位只要在 30 单位内就能开火（`World.ts:632-641`），`warning` 计时后发射；`emplacement` 还会一次散射 5 发（`World.ts:648-655`）。瞄准线由 `Renderer` 的 `warningLines` 绘制（`Renderer.ts:224-243`、`Renderer.ts:605-613`），与 D5 要删除的目标一致，由 05 统一处理。

### 1.3 水、云与地面系统的其它断点

- **水**：没有 `waterLevel`、没有水面高度、没有“这里是不是水”的查询，08 的浮筒/飞行艇（D6 要求水面支持，D8 给出浮筒/飞行艇构型）无法起降或停泊。
- **云**：云朵当前是随机 `y ∈ [6, 11]` 的贴片（`Renderer.ts:97-111`），与地面无关系；D7 要求云层按 `terrainHeight + 14/28/42` 分层（见 10），07 必须建立在本文的高度场上。
- **遮挡**：空中单位碰撞是纯 XZ（`World.ts:626-627`），地面火力没有视线/遮挡概念；地形起伏若只做视觉，山脊不会带来任何战术意义。

### 1.4 归纳

需求“地面单位太快、应沿固定路线、没有固定炮台”和“地面缺少起伏、需要完整地面系统”本质是同一个缺失：**战场没有一个模拟层可用的地面基准**。修法不是给地面单位打补丁，而是先建立 `terrainHeight` 这个单一事实来源，再把移动、渲染、相机、弹道、云和时代内容全部挂到它上面（D6）。

## 2. 目标体验

1. **有地貌的战场**：玩家在 360×640 的竖屏里能一眼看出山脊、河谷、海岸、道路和铁路；低空掠过山脊时能感到地形在脚下起伏。
2. **有生命的交通**：地面不再是一排“会转向的炮台”，而是沿公路/铁路持续行驶的车队与列车——它们有目的地、有队形、会排队、会从路口开来；玩家轰炸的是一支正在行进的车队，而不是一个悬挂在原地的靶子。
3. **空与地的关系可读**：地面单位不再追玩家，而是按路线移动、在射程内用提前量开火；威胁通过雷达/边缘指示（05）表达，不画瞄准线；炸毁道路上的一辆车会停在路边冒烟，其它车按车距排队继续行驶。
4. **不做的事**（避免把体验复杂化）：不做撞地坠毁、不做三维命中判定、不做导航网格、不做可破坏地形；高度层（`terrain+20`，10 §3.1）由系统自动维持（D6/D13）。

## 3. 目标设计（规则 / 数值 / 接口 / 表现）

### 3.1 确定性高度场

新增模拟层模块 `src/simulation/Terrain.ts`（**不 import three**，遵守 D11）。它是地面高度、水面、法线、道路压平的唯一事实来源，渲染层与模拟层共同调用。

```ts
// 建议接口（签名以 D6 的 terrainHeight(x, z) 为准）
export const TERRAIN = {
  seed: 20261120,       // 每局可由 World 种子覆盖；同种子同结果
  waterLevel: -1.5,     // D6 固定水位
  playAmplitude: 10,    // 可玩区常规起伏 0–10
  farPeak: 18,          // 远景山体上限
  chunk: 80,            // 10 §3.6：高空视野下 64 → 80
  nearSegments: 24,     // 625 顶点 / 1,152 三角形
  farSegments: 10,      // 121 顶点 / 200 三角形
  ring: 9,              // 9 块环绕
} as const;

// 基础地形：域扭曲 + 4 八度 fbm（0–9.2）+ 细节（0.8）+ 山脊（0–8.0）
function baseHeight(x: number, z: number, seed: number): number;

// 河道下切 + 道路压平后的最终高度
export function terrainHeight(x: number, z: number, seed = TERRAIN.seed): number {
  const wx = x + (noise2(x * 0.004, z * 0.004, seed + 11) - 0.5) * 18;   // 域扭曲 X
  const wz = z + (noise2(x * 0.004 - 5.7, z * 0.004 + 9.1, seed + 12) - 0.5) * 18;
  let h = fbm2(wx * 0.012, wz * 0.012, seed, 4) * 9.2;                   // 主体起伏 0–9.2
  h += fbm2(wx * 0.045, wz * 0.045, seed + 1, 2) * 0.8;                  // 细节 0–0.8
  const ridge = smoothstep(0.60, 0.76, fbm2(wx * 0.0035, wz * 0.0035, seed + 2, 3));
  h = Math.min(TERRAIN.farPeak, h + ridge * 8.0);                        // 山脊抬到 18
  h = riverCarve(h, x, z, seed);                                         // 河道中心压到 -3.5（水面下 2.0）
  return roadTerrace(h, x, z, seed);                                     // 道路压平 + 路肩 +0.35
}

// 供所有“贴地/落点/渲染”使用的最终表面：水面以下按水位算
export function surfaceHeight(x: number, z: number, seed = TERRAIN.seed): number {
  return Math.max(terrainHeight(x, z, seed), TERRAIN.waterLevel);
}
export function terrainNormal(x: number, z: number, seed = TERRAIN.seed): { x: number; y: number; z: number };
export function isWater(x: number, z: number, seed = TERRAIN.seed): boolean;
export function terrainSeedFrom(worldSeed: number): number; // World 种子 → 地形种子
```

**确定性规则**（D6/D11）：

- 高度只由 `(seed, x, z)` 决定，函数内**禁止** `Math.random()`、`Date.now()`、闭包计数器或任何玩家状态；噪声使用整数哈希（参考 `ShaderMaterials.ts:3` 的 `hash` 思路，但在 CPU 用整数位运算实现，不用 `sin` 哈希，避免不同设备浮点差异）。
- 同种子 + 同坐标必须逐位可重现（测试容差 `1e-9`）；不同种子必须产生不同地形。
- 高度是世界坐标函数，与玩家位置、块划分、LOD 档位、画质档位无关；LOD 只决定“采样多密”，不改变同一个 `(x, z)` 的高度。
- 高度范围：常规陆地 `0–10`（河道/海岸下切除外），山脊最高 `18`（`farPeak` 钳制），河床/海床 ≥ `-3.5`，水面恒为 `-1.5`；渲染层与模拟层不得各自维护第二套高度。
- 采样成本目标：单次 `terrainHeight` < 3µs；运行期每帧采样 < 200 次（玩家/敌机 ≤ 14×2、地面 ≤ 6×2、相机与防穿 2、阴影 ≤ 40、HUD 标签 ≤ 40），块构建采样单独摊销。

### 3.2 分块、LOD 与接缝

替换现有 9 块平地（`Renderer.ts:89-96`）：

| 项目 | 近景 LOD0 | 远景 LOD1 |
| --- | --- | --- |
| 块尺寸 | 80×80（见 10 §3.6） | 80×80 |
| 段数 | 24×24（625 顶点，1,152 三角形） | 10×10（121 顶点，200 三角形） |
| 使用条件 | 距玩家 < 110 单位 | 其余块（角块） |
| 法线 | 非索引三角形 + 每面 flat normal（Q 版低模） | 索引三角形 + 顶点平滑法线 |
| 材质 | 5 个表面分区的混合权重 | 草/水/路三色简化 |

- **9 块环绕**：以“相机前方 +Z 28 单位”为环心（相机 yaw 固定，`GAME_DESIGN.md:90-101`），`cx = round((x + 28) / 64) * 64`、`cz = round((z + 28) / 64) * 64`，覆盖前向约 156、后向约 86；与现有 `updateTerrain`（`Renderer.ts:445-456`）的 3×3 布局一致，只增加前向偏置与 LOD。
- **LOD 切换**：按“块中心到玩家距离 110”分档，切换加 8 单位迟滞，避免边界抖动；LOD 切换只换采样密度，不重建高度逻辑。
- **接缝处理**：三件事保证无缝——① 所有块使用同一世界坐标高度函数与同一世界对齐格点；② LOD 边界把 LOD0 边上顶点高度钳制到 LOD1 边的线性插值（共享边吸附）；③ 每块四边加 1.5 单位垂直裙边（约 +120 三角形/块）遮住残余裂缝。块内禁止叠加随机偏移。
- **流式更新**：环心变化一整块时只重建新进入的 3 块，单帧最多重建 1 块（其余在下一帧补），预算 < 1.5ms；重建过程中旧块继续显示，禁止整场闪烁。9 块共 ≤ 5 块 LOD0（约 5.8k）+ 4 块 LOD1（约 0.8k），标准档地面主网格目标 ≤ 9.5k 三角形（按 10 的高空视野上调）；低画质全部 LOD1。
- **远景山脊带**（对 D6 的细化）：9 块覆盖前向约 124、后向约 68，`18` 高度的远景山体若只在块内出现会很难看到；标准/高画质额外绘制一圈**非流式低模远景环**（12 个扇段，半径 160–520，约 1.6k 三角形，随同一环心整体平移并按世界坐标重采样），只做剪影与雾中轮廓；省电档关闭。它不替代 D6 的 9 块主网格，仅作背景层。
- **顶点属性**：`position`（真实高度）、`normal`、`surface`（0 草/1 路/2 沙/3 水/4 岩）、`roadMask`、`shoreMask`、`height`；由 CPU 在分块构建时写入，shader 只做颜色/细节/雾，不再位移高度。

### 3.3 道路、水系与桥梁

**生成顺序（避免模块循环依赖）**：

1. 由 `seed` 生成 `RouteNetwork`（纯 XZ 折线，见 §3.6，`src/simulation/Routes.ts`，不依赖高度）。
2. 用 `baseHeight` 计算河道与海岸：河流从高处按确定性梯度下切到海/湖，`riverCarve` 把河道压低到水位以下约 2.0；海岸/湖泊由低频 macro 噪声低于水位形成。
3. 路线网与水面求交：水面上的路段标记为**桥梁**，桥面高度 = `max(路线平滑高度, waterLevel + 2.2)`；没有桥的深水段从路线网中剪除（铁路必须过桥或绕行，由确定性规则决定）。
4. 道路压平：沿每条路线取 `baseHeight` 并做 9 点滑动平均得到路面基准，**路面压平到基准高度**（`roadMask` 内权重 1），两侧 4.5 单位内平滑过渡，路肩抬高 `+0.35`，路面抬高 `+0.06` 防止 z-fighting；与 D6“道路对高度场做平整”一致。
5. 渲染：道路不单独建面，走地形材质分区的 `roadMask`；铁路用实例化轨枕/钢轨（每块/每段一次构建，池化，约 2 个 draw call）；桥梁用实例化桥面板。

**水系渲染**：

- 水面为一个跟随环心的 384×384 大平面，`y = TERRAIN.waterLevel`，2 个三角形 + 轻量水面 shader（深浅双色、fresnel、低频法线扰动、岸线泡沫由 `shoreMask` 驱动）；不透明、先于地形绘制，深度写入；不做反射/实时折射，遵守 D10。
- 岸线：地形顶点距水位 < 1.2 标记沙地（surface=2）与 `shoreMask`，泡沫随时间轻微移动；避免透明排序问题。
- 与 08：道路材质按时代切换（萌芽期土路、一战泥泞车辙、二战沥青/铁路、喷气期混凝土跑道），色板由 08 统一给定，06 只负责分区与遮罩；水上飞机/飞行艇在 08 **一期只做浮筒构型与贴水/滑行表现**，完整水面起降玩法放到二期（需要与 D6“不做撞地坠毁”一起设计，见 §8-5）。

### 3.4 高度层与相对高度

**唯一规则**：玩家与空中敌人的视觉高度 = `terrainHeight(x, z) + 20`（在水面上取 `surfaceHeight + 20`，即 `max(terrainHeight, -1.5) + 20`，避免飞进水面以下），用阻尼跟随；所有依赖高度的表现都基于该相对高度，不再用固定 `y=4`（D6）。**高度/相机权威口径见 [10](10-altitude-layers-and-bombing-camera.md) §3.1–3.3，本文只保留地面接口。**

```ts
// 模拟层（World.step 内、位置积分之后）
const targetY = surfaceHeight(p.x, p.z);
p.prevY = p.y;
p.y = damp(p.y, targetY + 20, 5, dt);           // 约 0.5s 收敛，越过山脊时不跳变（10 §3.2）
// 空中敌人同理；地面单位 y = surfaceHeight(e.x, e.z) + 0.05；舰艇 y = waterLevel + 0.1
```

- **玩家**：`ProceduralAircraft.ts:387` 的 `this.group.position.y = 4 + ...` 改为读取 `player.y + 呼吸浮动`；`Renderer.ts:488-489` 的位置插值增加 `y/prevY`，转弯与爬升不抖动。

### 3.6 路线网与地面交通

**数据结构**（`src/simulation/Routes.ts`，不依赖 Three.js）：

```ts
interface RouteNode { id: number; x: number; z: number; kind: "junction" | "stop" | "bridge"; }
interface RouteEdge {
  id: number; a: number; b: number; kind: "road" | "rail" | "water";
  points: { x: number; z: number }[];   // 折线，每 ~6 单位一个采样点
  length: number; lane: number;          // 单向车道偏移（双向路 = ±1.6）
  bridge: boolean;
}
interface RouteNetwork {
  nodes: RouteNode[]; edges: RouteEdge[];
  sample(edgeId: number, s: number): { x: number; z: number; heading: number };
  nearest(x: number, z: number): { edgeId: number; s: number; dist: number };
}
```

- **确定性生成**：在活动范围内（`|x|, |z| ≤ 512`，覆盖 `RULES.boundary = 380`，`config.ts:6`）用带哈希抖动的格点（间距 90–140）生成路口，连接相邻节点并随机（哈希决定）加对角线，形成约 140–200 条边的公路网；铁路用更稀疏（间距 ~220）更直的独立网络；水路取 §3.3 的河流主干。全部由种子决定，生成一次并缓存，不随玩家位置变化。**不使用导航网格**，节点/边只做采样。
- **单位沿路线匀速行驶**：每个地面单位持有 `RoutePlan { edgeId, dir: 1 | -1, s, lane }`，速度 1.2–2.2 单位/秒（按类型固定，见 §3.7 表）；每帧 `s += speed * dt`，位置由 `sample(edgeId, s)` + 车道偏移得到，朝向取折线切线；到达路口时从相连边中按**预生成的确定性路线计划**选下一条（避免逐帧随机和掉头），用 25–30°/s 的转向阻尼“到达路点转向”。
- **排队**：每帧向前查询同边同向最近单位，间距 < 6.5 时目标速度降到前车速度，< 3.2 时停下；车队（资源车 2–3 辆）以 7 单位间距编队生成、同车道跟随。地面数量 ≤ 6（D3），O(n²) 比较足够。
- **与玩家无关**：车辆 `heading` 只来自路线切线，**永不朝玩家转向**；武器射击方向在开火瞬间计算（AA 车/导弹车可移动开火，flak 取 0.45s 提前量，导弹用追踪），可选的炮塔视觉朝向单独用 `turretHeading` 阻尼，不影响底盘朝向。
- **开火与告警**：射程 30–34（见 §3.7），进入射程后内部 `warning` 计时 0.8–1.3s，随后开火；开火时向 `World.events` 推 `ground_attack`（导弹为 `missile_lock_warning`），由 05 的雷达扇区/边缘指示消费；**不画瞄准线、不画预警线**（D5：删除 `Renderer.ts:224-243`、`Renderer.ts:605-613`、`Renderer.ts:787` 的 warningLines 相关代码）。
- **被击毁**：车辆立即把路线速度归零、沿路线位置停住，进入 8–10s 的 `wreck` 状态（冒烟/燃烧、不可选中、不再计分），随后移除；同路后车按排队规则减速通过（残骸不产生碰撞体）。
- **生成/回收**：在玩家前方路线节点/路段生成——距离玩家 52–88、优先玩家航向 ±60° 内、且满足“离屏近似”条件（距离 ≥ 52 且偏离正前方 > 0.7 rad，或距离 > 70；离屏的最终口径由 02 统一）；从节点处沿路线驶入视野。离玩家 > 90 时回收（D6），报废残骸 > 12s 移除。生成节拍与地面 ≤ 6 上限由 02 的导演负责，本文只提供“前方路线候选点”查询。

### 3.8 与云、水、时代内容的表现约定

- **云（07）**：云簇高度以 `terrainHeight(x, z) + 8 / 12 / 16` 表述（D7），每簇在生成时采样簇心地面高度并 `max` 到“地面 + 8”，保证云不会埋进山体；云底在高度场上漂浮，山脊会从云层中露出。

- **时代（08）**：道路/铁路/桥梁/路侧设施按时代换材质与密度；地形分区色由 08 的鲜艳色板接管；低模 flat shading 与 06 的 LOD 法线策略一致。

## 8. 待确认与备选

1. **`depot` 的最终定位**（推荐：保留为静态建筑目标，符合 D6）：备选是改名为可移动燃料车队、彻底消除静态单位；若采用备选，删除 `World.ts:998` 的固定爆炸逻辑并把它并入 `fuel_truck`。
2. **撞地/落水是否扣血**（推荐：不扣血，仅“地形接近”提示）：理由见 §3.4；若后续要加，必须先补垂直操控或自动俯仰，否则与单手竖屏操作冲突。
3. **可破坏地形/永久弹坑**：0.4 不做真实改高度（会破坏确定性、增加同步与性能负担）；仅用贴花/粒子/火焰区表现，0.5 再评估。
4. **远景环是否保留**：标准/高画质开启，省电档关闭；若评审认为 D6 的 9 块已足够，可删远景环并接受“远景 18”只在可玩区边缘出现。
5. **水面舰艇与水上飞机起降的范围**：06 只交付水面渲染 + `isWater`/`surfaceHeight` 接口；舰艇生成与浮筒起降交给 08 二期，避免 06 范围膨胀。
6. **雾/远裁剪数值**：按 10 §3.6 的 `70–240 / far 280` 执行；需与 07 云层、08 色板一起在目标机型上验收后固化。
7. **地面火力视线检查**：推荐做轻量地形遮挡检查（§3.4），省电档关闭；是否作为“山脊掩体”正式玩法需策划确认。
8. **铁路/桥梁是否 0.4 必做**：建议铁路必做（装甲列车依赖），桥梁至少做“压平 + 桥面高度”的简化版，复杂桥型留到 08 时代内容。
9. **`RULES.maxGround` 与总场上限**：D3 规定地面 ≤6、全场 ≤14，但当前 `config.ts:7-8` 是 `maxEnemies: 24 / maxGround: 14`；具体收敛由 02 统一改，06 只按 6 设计与测试。
